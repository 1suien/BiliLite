# 「这条线路不支持定位」修复（本机 0.4.62）

方案见 [docs/82-不支持定位方案.md](82-不支持定位方案.md)。

## 改了什么

### P0：不再卡在「已缓存 0:50」

`app/src/player/dash.ts`：

- `jumpWhenBuffered()`：跳转条件从 `buffered.end >= 目标` 放宽到 `buffered.end >= 目标 - 1.5s`（追加粒度常停在目标前一点，原来会永远等不到）；落到目标时把 `currentTime` 夹到缓冲尾前 0.05s；
- 新增 6.5 秒超时：仍没到目标就清状态、把播放位置挪到「已缓冲末尾 − 1s」并 `kickPlay()`，先让用户能看；
- 状态行改成带总时长与百分比：「这条线路不支持精准定位，正在顺拉 0:50 / 39:27（已缓存 32%）」，每约 1.2s 刷新一次，不再出现两个一样的秒数；
- 新增 `DashPlayerHooks.onSlowSeek(sec)`：超时时回调上层，让上层决定换流。

### P1：自动切到可定位流（durl）

`app/src/views/VideoView.vue`：

- 新增 `directMode` / `directLoading` 与 `switchToDirect(sec)`：收到 `onSlowSeek` 时调用 `bili.video.downloadUrl()`（`fnval=1` 的单文件 mp4，B 站 `durl`，原生支持 HTTP Range）→ 销毁 DASH 播放器 → 把 `<video>` 的 `src` 指到该地址 → `loadedmetadata` 后 `currentTime = 目标` 并播放；
- 成功后 toast「这条线路不支持精准定位，已切到可定位流」，状态行清空；
- 单文件模式下的控制适配：`togglePlay()`、`requestSeekTo()`（进度条/手势/快进都走它）、`onDirectTime()`（timeupdate 同步时间/时长/缓冲）；
- 切视频/重建播放器时退出单文件模式（清 `src`），避免串台；
- 失败（拿不到 durl）时 toast「切换可定位流失败：原因」，保留 P0 的「先播当前缓冲」行为。

## 验证

- `npx vue-tsc --noEmit` 通过、`npm run build` 通过；
- 浏览器 mock 播放页加载无 JS 异常，笔记条/清晰度工具栏仍在；
- 真机验证点：跳 0:50 应 3 秒内出画面；跳远处（无索引流）→ 状态行显示顺拉百分比，6.5 秒超时后自动切 durl 并跳到位。
