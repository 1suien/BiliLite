# 视频评论区方案（0.4.36 提案，先不写代码）

## 结论：能做，而且不需要登录

实测接口（本机直连 B 站）：

- 主评论（旧接口，未登录可用）：`GET /x/v2/reply?type=1&oid=<aid>&pn=1&ps=20&sort=2|1` → `code:0`，BV1zY4y187cK 返回 4,620 条评论；
- 楼中楼：`GET /x/v2/reply/reply?type=1&oid=<aid>&root=<rpid>&pn=&ps=10`；
- wbi 版 `/x/v2/reply/wbi/main` 未签名返回 `-403 访问权限不足`，所以先走旧接口，遇到 `-412/412` 再补 wbi 签名（项目里已有 `wbi.ts`，可复用）。

## 范围（这一版只做「看」）

| 做 | 不做（要登录/有风控/风险大） |
| --- | --- |
| 看评论列表、楼中楼回复 | 发评论、回复、点赞 |
| 热门/最新排序切换 | 发布带图评论 |
| 加载更多、展开回复 | 关注/举报/屏蔽词管理 |
| 显示 UP 主标识、点赞数、相对时间 | 视频内弹幕（独立功能，另议） |

## 数据层

`app/src/bridge/api.ts` 新增（都挂在 `bili.video` 上）：

```ts
video.comments(bvid?, cid?, opts: { pn: number; ps?: number; sort: 'hot' | 'new' })
  → { count: number; comments: CommentItem[] }
video.commentReplies(bvid?, cid?, root: number, opts: { pn: number; ps?: number })
  → { count: number; comments: CommentItem[] }
```

- `oid` 用视频的 `aid`（`video.view()` 已返回 `aid`，存在 `detail` 里直接用）；
- `CommentItem` 归一字段：`rpid / mid / uname / avatar / message / like / ctime / rcount / replies(最多 3 条预览) / isUp / location`；
- 头像走 `fixImageUrl`，图片评论**只显示「[图片]」占位**（不加载外链图片，避免图床跨域与加载慢）；
- 失败（-412/412/网络）自动重试 1 次，仍失败给「评论加载失败，点此重试」。

## 界面（在「简介 / 笔记 / 相关推荐」后面加一个「评论」tab）

```
[简介] [笔记(0)] [相关推荐] [评论 4620]

 热门 ⇄ 最新          ← 排序切换（默认热门）
 ┌──────────────────────────────────────────┐
 │ (头像) 昵称  UP  3天前                   │
 │        这条评论的文字内容……              │
 │        ♡ 128   回复 28                   │
 │        └ 展开 28 条回复                  │
 └──────────────────────────────────────────┘
 …（每次 20 条）
        [ 加载更多 ]
```

- **懒加载**：只有切到「评论」tab 才请求，切分P/换视频清空重载，不影响起播速度；
- 卡片显示：头像、昵称（UP 主带「UP」标签）、相对时间、正文（最多 6 行，超出折叠「展开」）、点赞数、回复数；
- 楼中楼：先展示接口给的 3 条预览，点「展开 N 条回复」懒加载 10 条/次；
- 空态/失败态都给出明确文案与重试按钮；
- 移动端窄屏：头像 28px、正文 14px、行距与其他 tab 一致，沿用全局亮/暗色变量。

## 验收清单

1. 打开任意视频 → 点「评论」→ 出现总数、默认按热门排序；
2. 切「最新」→ 列表顺序变化；
3. 「加载更多」→ 追加下一页且不重复；
4. 点某条评论的「展开回复」→ 显示楼中楼，再点「加载更多回复」继续追加；
5. 切分P/换视频 → 评论清空并按新视频重新加载；
6. 断网/接口报错 → 显示重试按钮，点重试能恢复；
7. 打开视频页不点评论时，起播时间不应变化（懒加载）。
