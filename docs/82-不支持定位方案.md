# 「这条线路不支持定位」的方案（本机 0.4.62）

## 现象

跳到 `0:50` 后画面一直转圈，状态行写着：

> 这条线路不支持定位，正在缓冲到 0:50（已缓存 0:50）

意思是：这条 DASH 流没有 `segment_base` / `sidx` 索引，播放器不能按字节直接续流，只能从 0 秒顺序往下拉，拉到 0:50 再跳过去。而现在**已经缓冲到 0:50 了却没跳**，卡在「差一点点」的判断上。

## 根因（两个）

1. **判断太严**：`jumpWhenBuffered()` 要求 `buffered.end >= target` 才跳；实际缓冲尾往往停在 `target - 0.2s` 附近（追加粒度/对齐），于是永远等不到 → 一直转圈；
2. **没有兜底流**：这条流本身没有索引，即使修好判断，远距离跳（比如 20 分钟后）仍要从 0 拉到目标，非常慢。

## 方案

### P0（马上修，0.4.62）

1. **放宽跳转条件**：`buffered.end >= target - 1.5s` 就跳（差 1 秒内用户无感）；
2. **加超时兜底**：等待 6 秒仍没到目标 → 直接从「当前缓冲位置」开始播放，状态提示「该线路不支持精准定位，已从 0:00 开始播放（到目标后自动跳）」；
3. **进度可见**：状态行显示「正在顺拉 0:50 / 39:27（已缓存 32%）」，不再只写两个一样的秒数；
4. 跳转成功后清掉 `usedFallbackFromZero` 标记，避免下次误判。

### P1（下一步，推荐）

5. **durl 兜底**：检测到「无索引」时，自动重新请求 `fnval=1`（mp4 单文件，B 站返回 `durl`，支持 HTTP Range 随机定位）并精确跳到目标位置，提示「这条线路不支持定位，已切到可定位流（1080P）」；
6. **记住标记**：该视频记住「无索引」→ 下次直接走 durl，不再尝试 DASH 顺拉（存 `progress` 旁的本地标记表或 localStorage，键 `bvid|cid`）；
7. 设置里加开关「无索引时自动换单文件流」（默认开）。

### P2（不做 / 以后）

8. 自己估算 moof 偏移（按平均码率猜字节位置再往前扫）——实现复杂、命中率不稳，收益不如 durl，先不做。

## 改动文件

- `app/src/player/dash.ts`：`jumpWhenBuffered()` 放宽条件 + 超时回退播放 + 状态文案（带时长/百分比）；
- `app/src/views/VideoView.vue`：无索引时显示「切到可定位流」按钮（P1 自动执行 + toast）；
- `app/src/bridge/api.ts`：复用现有 `videoDownloadUrl`（fnval=1）拿 durl（无需新接口）；
- docs/82（本文）+ 实现后 docs/83。

## 验收

- 跳到 0:50：3 秒内出画面；状态提示不再卡「已缓存 0:50」；
- 跳到 20:00（无索引流）：P0 会顺序拉并显示进度；P1 自动切 durl 后 2 秒内跳到位；
- 正常有索引的线路跳转不受影响（0.4.35 的 sidx 逻辑不动）。

## 三个默认（不回就按这个）

1. P0 立即做，P1 一起做（durl 兜底默认开，用默认清晰度）；
2. 超时 6 秒后自动播放当前位置，不弹窗打断；
3. 记住「无索引」的视频，下次直接用单文件流。
