# 18 退出播放页后再次播放，接着上一次的进度（本机构建 0.4.11）

> 本仓库自己的修复。上游 0.4.4 里没有这段逻辑（0.4.5 之后的小窗、笔记等都是本机定制）。

## 1. 用户报告

> 「播放退出后再次播放无法继续上一次的进度」

也就是：看了一会儿退出播放页，之后再打开同一条视频，没有接着上次看到的位置，而是从更早的位置（有时是开头）开始。

## 2. 复现与定位

### 2.1 关键证据：离开那一刻的进度没写进库

给 `flushProgress()` 临时加日志，在无头浏览器里真实走一遍「播放 5 秒 → 点左侧导航离开」：

```text
[flush] called { hasPlayer: true, hasEl: true, t: 5.4212, bvid: , cid: 181112 }
```

`t`（离开时的秒数）是对的，但 **`bvid` 是空串**。原因是：

- `flushProgress()` 里调 `progressData()`，而 `progressData()` 的 `bvid` 取自 `const bvid = computed(() => String(route.params.bvid || ''))`；
- `onBeforeUnmount` 触发的时机是**路由已经切走之后**，此时 `route.params.bvid` 已经是空串；
- `learn.save()` 第一行就是 `if (!p || !p.bvid || p.cid == null || p.cid === '') return null` —— 这条脏数据被**静默丢弃**了。

结果：离开前最后那段时间的位置根本没入库，只能靠播放中「每 5 秒定时写一次」的旧值，或者如果看得不到 5 秒就什么也没存下 → 再次播放自然不能接着上次的位置。

（同一类坑 0.4.8 已经踩过一次：`autoMiniOnLeave()` 里的 bvid 也来自路由，当时用 `openedBvid` 兜住了小窗；这次漏的是写学习进度这条路径。）

### 2.2 顺带发现：小窗气泡挡着「再次打开」

0.4.8 起，离开播放页会自动缩成右下角圆形小窗并暂停。这时从学习页「学习进度」再打开同一条视频，`loadPlayurl()` 开头命中：

```ts
if (mini.open && mini.bvid === bvid.value) { status.value = ''; return }
```

页面于是只显示「视频正在小窗播放 / 收回本页播放」的占位，不会播放。用户看到的是一个不播的播放器，「进度没有继续」的感受也有这一半。

## 3. 改动

只改 `app/src/views/VideoView.vue`（web 层，原生侧未动）。

### 3.1 写进度用本页实例的稳定 bvid

```ts
// 学习进度要写库的字段
function progressData() {
  const d = video.value as any
  const page = pages.value[pageIndex.value]
  return {
    // 本机定制 0.4.11：离开播放页时当前路由的 params.bvid 已经变成空串，
    // 这里必须用本页实例打开时的 bvid，否则 flushProgress() 写库会被 learn.save 当成脏数据丢掉，
    // 导致「退出后再次播放」只能退回到上一次 5 秒定时存的旧进度（或从 0 开始）。
    bvid: openedBvid || bvid.value,
    ...
  }
}
```

`openedBvid` 是 `onMounted` 里记下的本页实例打开的视频号（0.4.8 加小窗时已存在），不随路由变化。

### 3.2 再次打开同一条视频：把小窗收回本页并续播

`loadPlayurl()` 里原来的「同一条视频只显示占位」改成「收回本页 + 从离开时的位置继续」：

```ts
if (mini.open && mini.bvid === bvid.value) {
  const at = Number(mini.currentTime) || Number(mini.startTime) || 0
  mini.close()
  if (at > 0.5) resumeOverride = at
  status.value = ''
}
```

- `resumeOverride` 是模块级的一次性续播点，`startTime()` 优先返回它（用一次就清空），所以本页不用再改路由、也不会因为 query 变化而重建组件；
- 收掉气泡后正常拉流播放，进度环/时长/清晰度都使用本页这一份播放器状态。

效果：从学习页/搜索再打开同一条视频时，小窗自己消失、本页直接播放并接着上次的位置。

## 6. 升级说明

- 同 debug 签名，本仓库 0.4.3–0.4.10 可直接覆盖升级（versionCode `15 > 14 > … > 7`）；装过官方版需先卸载。
- 升级后**旧的学习进度不受影响**（数据库结构没改）：之前在旧版本里留下的进度会照常显示；这次修复只影响从今往后「退出时」能不能把当前位置存住。
- 已经被旧版本丢掉的那段时间无法找回，只会从旧版本最后一次成功保存的位置继续。

## 7. 未验证 / 已知限制

- 真机没验：安卓 WebView 上 `beforeunload`/`visibilitychange` 与 `onBeforeUnmount` 的时序和桌面无头 chromium 不完全一致（修复本身不依赖 `beforeunload`，但真机上「按 Home 键切后台」走的可能不是卸载路径，仍按 `visibilitychange` 的定时保存走）。
- 未改「看几秒不算进度」的既有规则：`saved.seconds < 4` 或「离结尾不足 12 秒」时仍从 0 开始（[VideoView.vue](../app/src/views/VideoView.vue) 的 `startTime()`）。
- 续播用 `resumeOverride` 一次性传值：如果收回小窗那一瞬间拉流失败，提示「重新获取播放地址」再试时会回到普通进度逻辑（从库里进度恢复），不会停在小窗那一秒。
