# 线路自动重试（本机 0.4.33）

## 背景

0.4.32 修好起播后，用户在真机上遇到另一类失败（同一视频、1080P DASH）：

```
地址 0.1s · 首块 0.2s · 首帧 0.2s · append 2次/0.0s · 0.0MB · 0.0MB/s
这条线路暂时拿不到数据   Failed to fetch @upos-sz-mirrorcos.bilibili.com
```

- 起播本身已经很快（首帧 0.2s）✅；
- 但拉媒体分片时目标 CDN 主机（`upos-sz-mirrorcos.bilibili.com`）直接 fetch 失败，等于这条线路拿不到数据；
- 旧逻辑只把错误卡片丢给用户，让他自己点「重新获取播放地址」。

B 站 playurl 每次都会返回一组 CDN 线路（`upos-sz-mirrorcos` / `mirrorali` / `mirrorhw`…），某一条被墙/被限速/临时故障时，**重新取一次播放地址通常就换到别的线路**。这个动作可以自动做。

## 改动（`app/src/views/VideoView.vue`）

| 位置 | 改动 |
| --- | --- |
| 新增 `isCdnError()` | 识别「线路/网络类」错误：`Failed to fetch`、`NetworkError`、`TypeError`、`拉流失败`、`net::ERR`、`加载失败` 等 |
| 新增 `handlePlayError()` | 播放器 `onError` 与 `player.load()` 抛出统一走这里：CDN 类错误自动清空错误卡片、状态栏显示「正在自动换线路（第 N 次重试）…」，900ms 后重新 `loadPlayurl()`（会重新请求 playurl，拿到新线路）；最多自动重试 **2 次**，仍失败才展示原来的错误卡片 |
| `loadPlayurl(manual)` | 用户手点「重新获取播放地址」时把重试计数清零（还能再自动试两轮）；重试时清掉起播慢提示计时器 |
| 成功加载后 | `cdnRetries = 0` 复位 |

行为变化：遇到 CDN 抖动不再需要用户手动点一下，页面会自己换线路；错误卡片只在连续 2 次自动重试都失败后出现。

## 限制 / 后续

- 如果整个网络到 B 站 CDN 都不通（比如开了代理/VPN 只放行部分域名），自动换线路也会失败，最后仍会出现错误卡片，可点「在浏览器打开」确认视频本身能否播；
- 更彻底的方案（暂未做）：连续失败后自动降一档清晰度（1080P → 720P），或把多条线路并行竞速取最快的那条。

## 怎么确认生效

再遇到拉流失败时，状态栏先出现「这条线路暂时拿不到数据，正在自动换线路（第 1 次重试）…」，随后画面直接出来——不需要再手点「重新获取播放地址」。
