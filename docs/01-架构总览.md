# 01 · 架构总览

BiliLite（本文以 0.4.3 产物为还原基线；0.4.4 增量只有版本号与安卓剧场模式 CSS，见 [docs/11](11-0.4.4同步记录.md)）是「**薄前端 + 厚原生桥**」结构：Vue 只负责渲染，所有网络、扫码登录、WBI 签名、Cookie、文件选择、备份写盘、画中画都在原生侧完成，通过**一个全局对象 `window.bili`** 暴露给前端。这个契约在 Android 和桌面 Electron 两个平台上是同一套，所以 UI 代码完全跨平台。

## 三层结构

```
┌──────────────────────────────────────────────────────────────┐
│ ① 渲染层（Vue 3.5 + vue-router 4 + pinia 2.3）  app/src/       │
│    App.vue / views / components / stores / player / styles     │
│    —— 只调用 window.bili，不直接 fetch、不碰 Cookie/签名       │
├──────────────────────────────────────────────────────────────┤
│ ② 数据桥（window.bili）  app/src/bridge/                       │
│    index.ts   → 延迟代理到 window.bili（未安装时抛可读错误）    │
│    types.ts   → 桥的 TypeScript 契约（WbiBridge）              │
│    android.ts → 安卓实现：37 个通道 + invoke/call              │
│    api.ts     → B 站接口封装 + 字段裁剪/映射                   │
│    http.ts    → CapacitorHttp 包装（超时/Abort/Set-Cookie）    │
│    wbi.ts     → WBI 签名（手写 MD5 + mixinKey 重排）           │
│    state.ts   → Preferences 持久化（设置/用户/Cookie）         │
│    mock.ts    → 【新增】浏览器演示用假桥                       │
├──────────────────────────────────────────────────────────────┤
│ ③ 原生壳（Capacitor 6 + Android）                              │
│    MainActivity(BridgeActivity) / PipPlugin / ImmersivePlugin  │
│    官方插件：App、Clipboard、Filesystem、Preferences、          │
│              ScreenOrientation、Share、StatusBar、Http、Cookies│
└──────────────────────────────────────────────────────────────┘
```

对应原始产物：

- ① 渲染层 = `assets/public/assets/*.js`（41 个 chunk）——入口 `index-jTHZJced.js` 里的 Vue 应用部分；
- ② 数据桥 = 同一个 `index-jTHZJced.js` 的后半段（约 2600 行里的桥 + 接口 + 签名 + 持久化）；
- ③ 原生壳 = `classes.dex`（Capacitor 框架）与 `classes4.dex`（`com.bililite.app.*`）。

> 为什么能确定：渲染层 chunk 里**完全没有** `fetch(`、`document.cookie`、`md5`、`w_rid` 之类的痕迹，而 `index-jTHZJced.js` 里全都齐备；桌面端还有另一个桥 chunk `index-B576k3Hi.js`，说明「桥」是可替换平台层。

## 启动时序（`app/src/main.ts` 的 `boot()`）

1. 给 `<html>` 打 `data-platform`（安卓/桌面）；
2. **选择桥**（三选一）：
   - 已有 `window.bili` 且 `platform !== 'android'` → 直接用（Electron 桌面端）；
   - URL 带 `?mock=1`，或 dev 模式且没有任何桥 → `installMockBridge()` + `seedDemoData()`【本工程新增的开发者工具】；
   - 否则 `await import('./bridge/android')` → `installAndroidBridge()`，这一步内部会：加载 Preferences 状态 → 恢复 B 站 Cookie → 准备 WBI 密钥缓存 → 安装 `window.bili`；
3. 安装原生能力：`installClipboard()`（剪贴板封装）→ `installFullscreen()`（`fullscreenchange` → 沉浸式 + 状态栏 + 横屏锁定）→ `installPip()`（画中画）；
4. `createApp(App)` + `createPinia()`；
5. **并行初始化 6 个 store**：`settings.init()`、`auth.init()`、`learn.init()`、`habits.init()`、`ups.init()`、`collect.init()`（本地数据全部从 Dexie 读）；
6. `app.use(router).mount('#app')`；
7. `installBackButton()`：安卓返回键优先级 = 关登录弹窗/确认框 → 退出全屏 → 剧场模式发 `Escape` → `history.back()` → 最小化/退出 App。

任何一步抛错，`#app` 会被写入「BiliLite 启动失败」+ 错误详情的 DOM，方便在真机 `chrome://inspect` 里排查。

## 一次典型数据流（播放页）

```
VideoView.vue
  → bili.video.view(bvid)            （window.bili）
  → bridge/android.ts handler 'video:view'
  → api.ts  →  wbi.ts 签名  →  http.ts (CapacitorHttp)
  → https://api.bilibili.com/x/web-interface/view?bvid=...
  ← {ok:true,data} 或 {ok:false,message,code,needLogin}
  ← d() 取 data，失败按 needLogin/biliCode 抛错
  ← 视图渲染；播放进度/时长同时写 Dexie（learn store）
```

- **服务端数据**（视频、UP、收藏夹、搜索）只经过桥，不落库（除了 `ups` 的最新投稿 5 分钟内存缓存）；
- **本地学习数据**（进度、每日时长、签到、习惯、专注、本地视频）只写 Dexie `study-bili`，永不上传；
- **用户设置 / 登录态 / Cookie** 由 `state.ts` 写 Capacitor Preferences（key `bililite.state.v1`），失败回退 `localStorage`。

## 状态管理划分（`app/src/stores/`）

| store | 职责 | 数据来源 |
|---|---|---|
| `auth` | 用户信息、登录/登出、扫码状态 | `bili.auth.*` + Preferences |
| `settings` | 主题/强调色/播放偏好/备份目录/专注目标 | Preferences（`bililite.state.v1`） |
| `learn` | 学习进度、每日时长、签到、学习清单、UP 时长分布 | Dexie（progress/daily/checkins/shelf/upTime） |
| `habits` | 习惯 CRUD、打卡日历、连续天数、提醒轮询 | Dexie（habits/habitLogs） |
| `ups` | UP 分组、最近投稿（5 分钟缓存）、导入 B 站关注 | Dexie（ups/upgroups）+ `bili.up.*` |
| `collect` | 本地收藏夹与条目（与 B 站收藏夹并列展示） | Dexie（collect/collectfolders） |
| `mini` | 小窗位置/尺寸（3 档），跨页保持 | `localStorage: study-bili-mini` |
| `ui` | toast、登录弹窗、全局刷新号、确认框、错误提示 | 内存 |
| `pomodoro` | 番茄钟：目标、计时、绑定视频、历史记录 | Dexie（focus）+ `localStorage: study-bili-pomodoro` |

> `pomodoro` 在原 chunk 里是 `FocusPanel.vue` 的普通 `<script>` 模块；因为 `FocusPanel`/`FocusTargets`/`FocusOverview`/`FocusRecords`/`LearnView` 都用到，本工程把它提成了 pinia store。

## 路由与布局

- hash 路由（Capacitor 的 `androidScheme: https` + `hostname www.bilibili.com` 下，webview 里用 hash 最稳）；
- 布局是**平板/桌面横屏**：左侧常驻导航栏 + 顶部搜索栏 + 右侧内容区，`global.css` 里**没有任何响应式断点**（只有 `prefers-reduced-motion`），所以窄屏会被挤压——验收截图统一用 1180×820；
- 没有 `<keep-alive>`：切换页面即销毁重建，靠 `ui.refreshSeq` 强制刷新（`<RouterView :key="route.fullPath + '#' + ui.refreshSeq">`）；
- 主题没有 CSS 类切换，而是 `applyTheme()` 把 `--accent/--accent-fg/--brand/--brand-soft/--brand-line/--brand-fg/--ring` 写到 `:root` 上，其余颜色走 `--bg/--card/--line/--t1..--t3` 等固定变量。

## 样式系统

- `app/src/styles/global.css`：从产物里**逐字节还原**的全局样式表（约 1369 行），包含 `:root` 变量与所有「无 scoped CSS」页面的类；
- `app/src/styles/recovered/*.css`：按 `[data-v-xxxx]` 从产物 CSS 里拆回来的组件级样式（`BiliImage/FavView/HabitView/Icon/LocalPlayerView/LocalView/SettingsView/UpManageView/PartList/CollectModal/PageFloat/Toasts/MiniPlayer/FocusTargets/FocusOverview/FocusRecords/FocusPanel/HabitHome`），拆的时候去掉了 `data-v` 属性与 keyframes 后缀；
- 组件的 `<style scoped>` 直接引用这些内容；`Icon.vue` 的 SVG 用 `innerHTML` 注入，52 个图标的 path 全部来自产物。

## 平台差异一览

| 能力 | Android（本工程桥实现） | 桌面 Electron | 浏览器 mock（本工程新增） |
|---|---|---|---|
| 数据源 | 真 B 站接口 + WBI + Cookie | 同左（由桌面进程代劳） | 内存假数据 |
| 扫码登录 | passport qrcode + poll | 同左 | 假 transition（waiting→scanned→success） |
| 文件选择 | `<input type=file>` + `android://` 伪路径 | 原生对话框 | 同名假数据 |
| 备份写盘 | Filesystem 写 Documents/Cache + Share | 直接写路径 | 返回假路径字符串 |
| 画中画/沉浸式 | PipPlugin / ImmersivePlugin | 不支持 | 不支持 |
| 媒体播放 | DASH/MSE + mpegts.js | 同左 | 假 URL，会被 CSP 拦 → 错误态 |

详见 [06-原生能力与安卓工程.md](06-原生能力与安卓工程.md)。
