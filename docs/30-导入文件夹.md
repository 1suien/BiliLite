# 导入文件夹（本机 0.4.23）：本地页多一个「导入文件夹」入口

> **本机改动（2026-10-28，Android 本机构建 0.4.23 新增 / 0.4.24 加固）**：本地页原来只有「本地导入」（选文件），
> 现在多一个「导入文件夹」：用系统 SAF 目录选择器选一个文件夹，安卓原生递归找出里面的
> 视频/音频，逐个复制进 App 私有目录 `local-media/`，再作为本地视频登记（可断点续播、边下边播）。

## 为什么不是 Web 端 `<input webkitdirectory>` 糊弄一下

WebView 里的 `<input type=file webkitdirectory>` 在旧 WebView 上不可用，选出来的文件也只能拿
`blob:` 地址（内存里临时存在，刷新就没），而本机 0.4.15 起本地导入的语义是「安卓 APK 复制进
App 私有目录，刷新、重启后还在」。所以文件夹导入走原生，顺带复用现成的复制/登记链路：

- 原生已存在：`pickAndImport`（选文件、ACTION_OPEN_DOCUMENT 多选）→ `importUris` 逐个
  `copyToMedia` 复制 → `describe` 生成条目（`url` 走 Capacitor 本地文件服务，Range 可播）。
- 新增只做两件事：**换一个 Intent**（`ACTION_OPEN_DOCUMENT_TREE` 选目录）、**递归把目录树里的
  音视频文件 collect 成 Uri 列表**，之后完全复用 `importUris` 的复制与登记。

## 实现链路（改动文件）

| 层 | 文件 | 改动 |
|---|---|---|
| 原生 | `app/android/app/src/main/java/com/bililite/app/LocalMediaPlugin.java` | 新增 `pickFolderAndImport`（`@PluginMethod`，`ACTION_OPEN_DOCUMENT_TREE`）、`folderPickResult`（`@ActivityCallback`，拿 tree Uri 后后台线程递归 + 复制）、`walkTree`（`DocumentsContract` 查子项、最多 8 层 / 300 个、按扩展名或 MIME 收视频/音频）；新增 `android.provider.DocumentsContract` import |
| 桥接类型 | `app/src/bridge/types.ts` | `local.pickFolderImport?(): Promise<LocalPickResult>` |
| 桥接实现 | `app/src/bridge/android.ts` | 注册插件方法 `pickFolderAndImport`；handlers 加 `'local:pickFolderImport'`；`bili.local.pickFolderImport()` 包装 |
| 应用入口 | `app/src/bridge/index.ts` | `local.pickFolderImport()` 包装（原生没有该方法时回退 `pickFolder()`，兼容旧壳） |
| 浏览器 mock | `app/src/bridge/mock.ts` | `pickFolderImport()` 返回 mock 条目，`npm run dev` 可点 |
| 界面 | `app/src/views/LocalView.vue` | 头部与空状态各加「导入文件夹」按钮（`data-local-folder`）；`importFolder()`：选目录 → 非空则 `importEntries`；无视频时 toast 提示 |

### 关键细节

- **递归只在原生做**：`walkTree(treeUri, parentDocId, out, depth)` 用
  `DocumentsContract.buildChildDocumentsUriUsingTree` 逐层 query 子项，目录 → 递归，文件 → 按
  `isMediaName(name)` 或 MIME `video/*` / `audio/*` 收集；上限 8 层、300 个文件，防止误选整张
  SD 卡导致卡死。
- **后台线程**：`folderPickResult` 把递归 + 复制放到 `local-media-folder` 线程（大文件夹要几十秒，
  不能堵主线程）；`call.resolve` 在线程里回，Capacitor 允许。
- **权限**：`ACTION_OPEN_DOCUMENT_TREE` + `FLAG_GRANT_READ_URI_PERMISSION` 即可读目录树，
  不需要 READ_EXTERNAL_STORAGE；顺手 `takePersistableUriPermission`（个别 ROM 失败不影响本次）。
- **去重/失败**：完全复用 `importUris`：同名文件自动 `-1/-2` 后缀、单个失败跳过、成功条目写入
  `local-media` 记录（同 `pickAndImport`）。

## 限制

- 只复制「视频/音频」文件（扩展名白名单 `MEDIA_EXTS` 或 MIME），图片/文档会被跳过。
- 上限 300 个文件 / 深度 8；超过部分不导入（不会截断报错，只是静默到上限）。
- 个别 ROM 把 DocumentsUI 裁了：原生会 `reject` 并提示改用「本地导入」选文件。
- 浏览器预览里「导入文件夹」走 mock，不会真的读目录（浏览器没有目录权限）。

## 验收路径

1. 本地页 → 点「导入文件夹」（或空状态的同名按钮）→ 系统目录选择器选一个有视频的文件夹。
2. 返回后本地列表出现该文件夹里的视频/音频（名称、时长、封面与「本地导入」一致）。
3. 杀掉 App 重开：条目还在（已复制进私有目录），点开可播放、可拖动进度（Range 请求）。
4. 「本地导入」旧路径（选文件）行为不变；无视频的文件夹会 toast「这个文件夹里没找到视频/音频文件」。
5. `npm run dev` 浏览器预览：按钮可点，返回 mock 条目（不报错）。

## 0.4.24：修「无法导入文件夹」

0.4.23 上线后反馈点「导入文件夹」不能用。**最可能的原因**：Android 11+ 的包可见性——`pickFolderAndImport`
启动前先用 `intent.resolveActivity(getContext().getPackageManager())` 预判有没有系统选择器，但
`AndroidManifest.xml` 里没有声明 `<queries>`，`resolveActivity` 对 `ACTION_OPEN_DOCUMENT_TREE` 会
返回 `null`，于是直接 `call.reject("这台设备没有可用的系统文件夹选择器…")`，用户看到的就是按钮点了
马上失败/提示没有选择器。

### 修复了什么

| # | 改法 | 说明 |
|---|---|---|
| 1 | **不再预判**，直接 `startActivity` | 启动 Activity 本身不受包可见性限制；只有真的没有选择器时才抛 `ActivityNotFoundException`，在 `catch` 里 reject |
| 2 | `AndroidManifest.xml` 补 `<queries>` | 声明 `OPEN_DOCUMENT_TREE` / `OPEN_DOCUMENT` / `GET_CONTENT` 三个 intent，`resolveActivity` 才看得见系统选择器（也给诊断用） |
| 3 | 失败自动退化 | `LocalView.importFolder()` 捕获原生 reject 后 toast 说明原因，并自动改用「本地导入」的选文件（可多选），按钮不会是死键 |
| 4 | 错误文案带诊断 | reject 消息里附 `sdk=… resolveTree=… treeActivities=… resolveDoc=… docActivities=…`，再出问题直接把这段话发出来即可定位 |
| 5 | `FLAG_GRANT_PERSISTABLE_URI_PERMISSION` | 选完目录后 `takePersistableUriPermission` 才可能成功（失败也不影响本次读取） |

### 0.4.24 验收

1. 本地页点「导入文件夹」→ 系统「选择文件夹」界面弹出（Android 11+ 底部有「使用此文件夹」按钮）。
2. 选中一个目录 → 里面的视频/音频出现在本地列表（复制进私有目录，重启还在）。
3. 如果设备确实没有 DocumentsUI：弹出 toast 并**自动跳到选文件界面**，能继续用「本地导入」。
4. 若仍失败：把 toast 里的完整文案（含 `sdk=… resolveTree=…`）发出来，可判断是包可见性
   （`resolveTree=no` 但 `treeActivities=0`）还是 ROM 真的裁掉了选择器。
