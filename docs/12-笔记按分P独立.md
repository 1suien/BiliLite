# 12 本机构建 0.4.5 —— 笔记按分P独立 + 回车换行

> 这是**本仓库自己的定制改动**，上游（官方 BiliLite）0.4.4 里没有这两项。改动完成后重新出了 APK：`BiliLite-0.4.5-debug.apk`（versionCode 9 / versionName 0.4.5），0.4.4 的官方同源产物仍保留。

## 1. 用户报告

用户在 Android 平板上用本工程产物学习「新概念英语 第一册」——那是一个 199 个分P的合集。反馈两件事：

1. **「每个视频笔记独立」**：在一个分P下写的笔记，切到别的分P还能看到；用户要的是每个分P（课时）只看到自己的笔记。
2. **「笔记回车不保存而是下一行」**：输入框里按回车会直接把笔记存掉，没法写多行。

原实现（还原自官方 0.4.3/0.4.4 的 web 层）确实是全局一份笔记：`loadNotes()` 只按 `bvid` 过滤 `db.notes`，同一视频的所有分P共用；输入框是单行 `<input @keyup.enter="saveNote">`，占位文案就是「记录当前时间点（…）的想法，回车保存」，回车即存。

## 2. 改动清单

### `app/src/views/VideoView.vue`

| 位置 | 改动 |
|---|---|
| `loadNotes()`（733–744 行） | 仍按 `bvid` 查 `db.notes`，再用 `String(n.cid) === String(cid.value)` 过滤，只留当前分P；注释「按「视频 + 分P」独立」 |
| `loadAll()`（716–721 行） | 初始分P确定后，**先** `loadRelated()` + `loadNotes()`，**再** `await loadPlayurl()`。原来笔记要等拉流结束才加载，拉流慢/失败（实机会出现「这条线路暂时拿不到数据」）时笔记区一直空白 |
| `loadAll()`（680 行） | 重载时清空草稿 `noteText.value = ''` |
| `selectPage(i)`（1097–1106 行） | 换 P 后清空草稿，并 `await Promise.all([loadPlayurl(), loadNotes()])` 重载该 P 的笔记 |
| 笔记模板（1579–1600 行） | 单行 `<input>` → 多行 `<textarea v-model="noteText" class="input note-input" rows="2">`；`@keydown.enter` 不再绑定保存（回车＝换行），改为 `@keydown.ctrl.enter` / `@keydown.meta.enter` 保存；占位文案改「记录当前分P（…）的想法；回车换行，Ctrl+Enter 或点「保存」存到本地」；空态文案与笔记正文行高同步调整（正文 `white-space: pre-wrap` 保留换行） |
| `saveNote()`（1176 行） | 未改：仍写 `{ bvid, cid, sec, text, at }`，`trim()` 后为空则忽略 |

### `app/src/styles/global.css`

新增 `textarea.input`（344–352 行）：`flex: 1; min-width: 0; font-family: inherit; font-size: 12.5px; line-height: 1.55; resize: vertical; min-height: 54px`。浏览器给 textarea 的默认等宽字体/字号与 `.input` 不一致，这里对齐单行输入框；`resize: vertical` 让用户能拉高。

## 3. 为什么切分P后要重新点「笔记」tab

`App.vue:346` 的 `<component :is="Component" :key="`${route.fullPath}#${ui.refreshSeq}`" />` 决定：换分P时 `selectPage()` 里 `router.replace({ query: { p: i + 1 } })` 会改 `route.fullPath`，**整个播放页组件重建**——tab 回到「简介」、播放器重建、`loadAll()` 重跑。所以笔记是按新实例的 `loadAll()` 加载的，`selectPage()` 里那次 `loadNotes()` 只是给重建前的旧实例收尾。真机上的表现就是：切 P 后回到「简介」tab，点「笔记」即可看到该 P 自己的笔记（与官方行为一致，本改动没有动路由结构）。

## 4. 验证

浏览器 mock 环境（`tools/browser` 的 playwright + `vite preview`）跑了一遍端到端脚本 `tools/browser/check-notes.mjs`（`node tools/browser/check-notes.mjs`，9/9 通过）：

1. 回车插入换行、不写入笔记（文本框值变成 `第一行\n第二行`，笔记数仍 0）；
2. 点「保存」写入 1 条；
3. 多行原文保留（换行不丢）；
4. 保存后输入框清空；
5. 切到 P2 后笔记 0 条；
6. P2 存一条后切回 P1，只看到 P1 自己那条；
7. 换 bvid（`BV1mock0002`）看不到上一个视频的笔记；
8. 无 console error / pageerror（mock 播放器的 `mock://` 地址被 CSP 拦截属预览环境噪音，已排除）。

另外：`npm run typecheck` 0 错误；`npm run build` 通过。UI 在 1180×760 与 1220×800（平板）下截图确认：多行文本框、笔记正文换行、保存按钮底部对齐都正常。

## 6. 升级与兼容

- 与 0.4.4 同签名（debug），`adb install -r` 可直接覆盖升级；versionCode 9 > 8，系统不会拦。
- **已有笔记**：旧版本写入的 `db.notes` 记录本来就带 `cid` 字段，升级后会自动按分P归位——之前各分P混在一起看到的笔记，升级后只在当初写下它的那个分P里出现，不会丢，也不再跨 P 显示。
- 数据库 schema 没变（`notes: '++id, bvid, cid, at'`，v1 起就是这个索引），不存在迁移。

## 7. 未验证 / 已知限制

- 未在真机软键盘上实测「回车＝换行」：Android 系统键盘的 Enter 在 textarea 里默认就是换行，理论上没问题；软键盘上没有 Ctrl，保存需要点「保存」按钮。
- 没有做「笔记编辑」功能；原实现每条笔记右侧有「▶ 跳转」（跳到记录的时间点）与「🗑 删除」两个按钮，0.4.7 起按用户要求**去掉了跳转按钮**、删除按钮挪到整行最右（详见 [14-小窗圆形气泡与笔记行按钮.md](14-小窗圆形气泡与笔记行按钮.md)）。
- 长按选中、粘贴多行文本没有专门测试（textarea 原生行为）。
- 平板竖屏/手机窄屏下这页本来就是桌面式布局（左侧固定导航），笔记行的换行效果在 430px 宽度下会挤，属既有布局问题，本次不改。

## 8. 后续（本机构建 0.4.7）：笔记行按钮

用户在平板上又提了两处界面调整（m01253）：

> 「1去掉花圈的部分，删除放在右边」

即：每条笔记右侧原来有「▶ 跳转 / 🗑 删除」两个按钮，截图里被圈住的是 ▶ —— 不要跳转，删除按钮放到这一行最右边。

0.4.7 的改法（细节见 [14-小窗圆形气泡与笔记行按钮.md](14-小窗圆形气泡与笔记行按钮.md)）：

- 删掉「▶ 跳转」按钮与 `jumpNote()` 函数（`player.seek(note.sec)`），时间点文字也不可点——用户明确选了「完全不要跳转」；
- 笔记行改成三列网格 `62px | 正文 | auto`，删除按钮 `justify-self: end`，贴在这一行最右侧；
- 正文仍 `white-space: pre-wrap` 保留换行。
