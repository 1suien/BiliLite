# 总时长显示错误修复（本机 0.4.39）

## 现象

用户反馈：某个视频原时长近 2 小时，App 里进度条却是 `1:13`，看起来「只有几分钟」。

## 根因（单位不统一）

播放器的内部约定是 **`dash.duration` 用毫秒**（`player/dash.ts` 里 `this.duration = payload.dash.duration / 1000`），
但 `bridge/api.ts` 组装 `PlayUrl` 时把 B 站接口返回的 **秒**（如 `7147`）直接放了进去。

于是：

- `dash.ts` 里 `7147 / 1000 = 7.147` 秒 → `MediaSource.duration = 7.147`；
- 媒体元素实际缓冲到 73 秒时就上报 `duration=73`，`VideoView` 的 `onTime` 又用小值覆盖了已知时长 → 进度条显示 `1:13`；
- 同时进度条、跳转、剩余时间全部跟着错。

## 修复

| 文件 | 改动 |
| --- | --- |
| `app/src/bridge/api.ts` | `dash.duration` 统一 `× 1000` 存毫秒（与内核约定一致）；`PlayUrl.duration` 对外仍换回秒 |
| `app/src/views/VideoView.vue` | `onTime`/`onDuration` 不再用更小的元素时长覆盖已知时长（`dur > duration.value` 才更新） |
| `app/src/player/dash.ts` | 建流时取「已知时长 / durationHint」里较大的可信值；`getDuration()` 遇到元素时长明显小于已知总时长（只 append 了一小段）时返回已知值 |

## 验证（冒烟，真数据）

用真实 playurl 数据在浏览器里跑（屏蔽 CORS），修复前 `ms.duration = 7.147`、进度条 `0:00 / 0:07`；
修复后 `ms.duration = 7147`、`video.duration = 7147`、进度条 `0:00 / 1:59:07` ✅
