# 拉流空闲看门狗（本机 0.4.44）

## 问题

视频《世界上最治愈的钢琴曲♪卡农》（BV1L4411U7Fj P1，1080P）点开后一直「缓冲中…」30 秒不动，调试行：

```
地址 0.3s · 首块 0.2s · append 2次/0.0s · 0.0MB · 0.0MB/s
```

接口拿到了地址（0.3s），视频/音频两个 init 段也 append 了（2 次），但之后**一个媒体字节都没来**，也没有错误卡片 → 不是请求失败，而是**请求挂起**。

## 原因

`app/src/player/dash.ts` 的 `streamFrom()` 只有「首包超时」（8s），而且首字节一到就清掉定时器。CDN 返回响应头、发完 init 段后不动时，`reader.read()` 永远挂着：

- 没有「空闲超时」把这条线路判死；
- 因为没有抛异常，0.4.33 的「CDN 错误自动换线路」也不会触发；
- 调试行里看不到当前线路 host（在 fetch 返回后才有，这条路径没走到）。

## 改动

### `app/src/player/dash.ts`

- 新增常量 `IDLE_TIMEOUT = 6000`、`IDLE_TICK = 800`；
- `streamFrom()` 每一路都挂一个空闲看门狗：每 800ms 检查一次「距上次收到字节是否超过 6s」，超过就 `abort()` 当前请求、记 `stat.retries++`、状态栏提示「这条线路拉不动，正在换线路…」，然后换下一条备用 URL；
- **背压期和 append 期间会刷新 `lastDataAt`**（否则缓冲满、暂停读的时候会被看门狗误杀）；
- `stat.host` 每次请求都更新，调试行能看到当前线路；
- 所有线路都空闲超时 → 抛 `线路 xxx 6 秒没有新数据` 的错误，交给 UI。

### `app/src/views/VideoView.vue`

- 新增 `isStallError()`：识别「没有新数据」类错误；
- `handlePlayError()`：空闲超时先**自动重新取一次播放地址**（700ms 后 `loadPlayurl()`，`stallRetries < 1`），避免用户手动点；
- 错误卡片新增「换 720P 试试」按钮（当前清晰度 > 720 时显示）：把 `defaultQuality` 降到 720P 重新取流（`retryLowerQuality()`）；
- 调试行新增「换线 N 次」。

## 验收

- `npx vue-tsc --noEmit` 通过、`npm run build` 通过；课表回归 33/33；
- 逻辑自测：空闲看门狗只在「连上后 6s 没有新字节」时触发，背压/append 期间不会误触发；
- 产物：`BiliLite-0.4.44-debug.apk`（4,174,709 B，sha256 `6dfa1dc25e5543a93037d9a5548b59368204fccd9a5e6291fb6d9488a0d52bf0`，versionCode 48 / versionName 0.4.44），`/dl` 200。

## 真机验证要点

1. 再打开那条卡农视频：6 秒内应该自动换线路并起播（状态栏会闪一下「正在换线路」）；
2. 如果 1080P 全挂：错误卡片点「换 720P 试试」；
3. 调试行里能看到 `换线 N次` 和 host；
4. 正常视频起播/拖进度不回归。
