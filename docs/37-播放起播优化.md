# 播放起播优化（本机 0.4.32）

## 现象（用户截图 2026-11-03）

播放《新概念英语第三册》P26（1080P，DASH）时一直转「缓冲中…」，约 16 秒才出画面。调试行：

```
地址 0.2s · 首块 0.2s · 首帧 16.4s · sz-mirrorcos · 5.5MB · 25.6MB/s
```

- `地址 0.2s`：拿 playurl 很快；
- `首块 0.2s`：第一段数据 0.2 秒就 append 完了（**数据不慢**）；
- `首帧 16.4s`：真正开播用了 16 秒；
- `5.5MB / 25.6MB/s`：拉到的数据很快就到位，之后停下——像是「播放迟迟没起来，缓冲到上限后停了」。

结论：**不是网速问题，是「数据就绪后没有立刻起播」**。

## 原因分析（`app/src/player/dash.ts`）

1. `load()` 末尾是 `await this.video.play()`——`play()` 要等到真正开始播放才 resolve，于是 `load()` 被挂住，`status('')` 清理、界面状态更新都跟着推迟；这期间一直显示「缓冲中…」。
2. WebView 偶发把 `play()` 当成非用户手势自动播放拦掉，原来的代码只 `catch` 一下，之后就没人再叫醒播放器了（`wasPlaying` 被置 false，看门狗也没有）。
3. 没有「媒体已可播但还停着」的兜底：数据早到了也不会补一次 `play()`。
4. 调试行只有「首块 / 首帧」两段，看不出卡在「数据就绪」还是「能播」还是「真开播」。

## 改动清单

| 文件 | 改动 |
| --- | --- |
| `app/src/player/dash.ts` | `DashStat` 增加 `tReady`（首个可播放数据）/`tCanPlay`（媒体元素 canplay）/`tPlay`（play() 真正开播）/`appends`/`appendMs` 计时 |
| 同上 | `waitFirstBuffer()` 成功时记 `tReady`；`attach()` 里监听 `canplay` 记 `tCanPlay` 并清掉「缓冲中…」；`playing` 记 `tPlay` |
| 同上 | `append()` 记录 append 次数与耗时；**首个视频分片 append 成功立刻 `kickPlay()`**（不等整段缓冲） |
| 同上 | `load()` 里 `play()` 改为**不阻塞**（`.then` 记 `tPlay`，`.catch` 落 `wasPlaying=false` 并提示「点一下画面开始播放」）；不再 `await` |
| 同上 | 新增起播看门狗 `startPlayWatchdog()`：媒体可播但一直 paused 时每 300ms 补一次 `play()`（最多 12 次），仍不行就提示点击画面 |
| `app/src/views/VideoView.vue` | 调试行增加「就绪 / 可播 / 播放 / append N次 Xs」；新增 6 秒起播慢提示：仍无首帧且暂停 → 状态栏「起播较慢：点一下画面开始播放」（点画面本来就能播放/暂停） |

## 新版调试行怎么读

```
地址 0.2s · 首块 0.2s · 就绪 0.5s · 可播 0.6s · 播放 0.8s · 首帧 0.9s · append 12次/0.4s · sz-mirrorcos · 5.5MB · 25.6MB/s
```

- `就绪 → 可播 → 播放` 三段能直接看出是「数据慢」「解码慢」还是「播放没起来」；
- 如果 `就绪` 就很慢（>3s），问题在拿流/appendsite；
- 如果 `就绪` 快、`播放` 慢，是自动播放被拦或解码慢——点一下画面即可，属于我们这次补上的兜底路径。

## 还没做的（看真机结果再定）

- 起播超过阈值自动降一档清晰度（1080P → 720P）；
- 续播（上次进度）时若续流失败，直接从 0 秒播，不按进度位顺拉；
- 播放器层结构化日志落盘，方便你在设置里导出。
