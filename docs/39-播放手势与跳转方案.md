# 播放手势与跳转方案（0.4.34 预研，先方案后代码）

> 用户需求（2026-11-06）：
> 1. 屏幕左右滑动可以调节进度；
> 2. 点击进度条过多会「无法加载」，要修。

## 一、现状（代码依据）

| 位置 | 现状 |
| --- | --- |
| `app/src/views/VideoView.vue:1174` `onSeekPointerDown` | 进度条按下只更新显示时间，**松手**才 `player.seek(pct*duration)`；但连续快速点/拖 = 连续多次 seek |
| `app/src/player/dash.ts:1430` `seek(sec)` | 只把 `video.currentTime` 设成目标；目标不在缓冲里时靠 `seeking` 事件触发重建 |
| `app/src/player/dash.ts:1338` `onSeeking()` | 目标不在已缓冲区间 → `restarting = true` → **重开一次 MediaSource 从新位置续流**（`openDash(payload, at)`）→ 恢复播放；期间 `restarting` 会忽略新的 `seeking` 事件 |
| `app/src/player/dash.ts:540` | `video.on('seeking')` 直接挂 `onSeeking` |

由此得到两个问题：

1. **没有手势**：只能点/拖底部进度条，不能像 B 站 App 那样在画面上横滑调进度；
2. **连点进度条会炸**：每点一次就是一次「重建 MediaSource + 从新位置拉流」。点击过快时会出现：
   - `restarting` 期间的新点击被忽略（看起来「点了没反应」，用户更容易继续猛点）；
   - 连续重建互相打断（`gen` 递增、旧拉流 abort），最后一次可能落在半路 → 表现为「一直加载 / 无法加载」；
   - 旧位置的 `seeking` 事件在重建后被再次触发，可能形成一次多余的二次重建。

## 二、方案 A：画面区域左右滑动调进度

### 交互

- **手势区**：视频画面 `.stage` 区域（不覆盖底部控制条、不覆盖右侧按钮）。
- **判定**：`pointerdown` 记录起点，移动超过 10px 且横向位移 > 纵向位移 → 进入「进度手势」模式（否则按老逻辑：点按 = 播放/暂停）。
- **过程中**：显示浮层，例如
  `⏩ 快进 +36s → 12:34 / 33:35`（往右为正、往左为负），同时画面轻微位移/亮度提示（可选）；控制条自动隐藏。
- **松手**：只调用一次 `player.seek(目标)`；不改变播放/暂停状态（原来在播就继续播，原来暂停就停在目标位置）。
- **取消**：手指滑回起点附近或滑出画面 → 取消，不跳转。

### 灵敏度

- 全屏宽度对应 **±120 秒**（默认），按视频时长自适应：
  `秒 = round(dx / 屏宽 * min(120, duration/20))`，即 33 分钟的课对应满屏 ±99s 左右；
- 拖动过程中浮层实时显示目标时间，松手取整到 1 秒；
- 目标夹在 `[0, duration-0.4]`。

### 边界

- 与控制条、弹幕开关、右侧清晰度面板互不抢手势（这些区域不进入手势判定）；
- 拖动时不触发播放/暂停（点按判定阈值 10px）；
- 桌面浏览器同样生效（鼠标按住拖 = 横滑）；
- 可选（P2）：双击左半屏 −10s、双击右半屏 +10s（沿用设置里的 `seekStep`）。

## 三、方案 B：跳转防抖与串行化（修「点多了无法加载」）

目标：**无论点多快、拖多少次，最多只有一个重建在飞，最后落地的是你最后一次指定的位置。**

### 1. 进度条改造（`VideoView.vue`）

- 拖动中只更新预览时间 + 浮层小气泡（不动播放器）；
- `pointerup` 才 `player.requestSeek(target)`；
- 拖动期间给 `.progress` 加 `seeking` 状态（进度条高亮），并抑制控制条自动隐藏；
- 同一次按住里只有一次 seek（现在其实就是这样，但拖动过程会因 `pointermove` 反复改显示；保持）。

### 2. 跳转队列（`dash.ts`）

新增对外接口 `requestSeek(sec)`：

```
requestSeek(sec):
  目标 = clamp(sec)
  if 目标与当前 currentTime 差 < 0.5s 且已缓冲 → 直接返回（忽略重复点击同一处）
  if 正在跳转（seekInFlight）:
      pendingSeek = 目标          # 只记最后一个
      return
  seekInFlight = true
  doSeek(目标)                    # 内部：缓冲内直接 currentTime；否则重建一次
  finally:
      seekInFlight = false
      if pendingSeek != null 且与已落地位置差 > 0.5s:
          取出 pendingSeek 再跳一次
```

- `onSeeking()` 里对元素原生 `seeking` 事件仍然处理（用户直接拖系统进度或不走队列时），但**统一收敛到同一把锁**，避免并发重建；
- 重建失败（openDash 抛错 / 超时）→ **自动重试 1 次**（同一目标）；仍失败才 `onError` 显示错误卡片；
- 跳转完成后再等 300ms 才允许下一次重建（防抖窗口）；
- 重建期间状态栏固定显示「正在跳转…」，不清空错误卡片以外的内容。

### 3. 状态与反馈

- 跳转中：进度条拇指位置 = 目标位置（灰显），状态栏「正在跳转…」；
- 落地后：立刻恢复播放（原状态），状态栏清空；
- 连续点 20 次：只应看到最多 1–2 次「正在跳转…」，最终停在最后一次点击的位置。

## 五、验收

1. 画面横滑 100px（约屏宽 1/7）→ 目标约 ±17s，浮层显示准确，松手后画面直接到该处；
2. 横滑中途反向/取消 → 不跳转；
3. 点按画面（位移 < 10px）→ 只切换播放/暂停，不跳转；
4. 连续快速点击进度条 20 次 → 不报错、不出现「无法加载」，最终停最后一次点击位置（3 秒内完成）；
5. 拖动进度条 → 全程只在松手时跳一次；
6. 跳转中状态栏「正在跳转…」，完成后恢复播放；
7. 跳转到未缓冲区域（如 20:00）→ 自动重建并继续播，不出现红卡片；
8. 课表/本地/搜索等页面无回归（回归脚本 33/33）。

## 六、需要你拍板的 3 个点

1. **横滑灵敏度**：全屏宽 = 120 秒（默认），还是按视频时长自适应（33 分钟课 ≈ ±99s）？还是更灵敏（满屏 = 60s）？
2. **要不要双击**左/右半屏 −10s / +10s？（B 站有，抖音也有；可做成设置项）
3. **跳转时是否自动暂停**：默认**保持原状态**（推荐，跳完继续播）；如果你希望跳转时先暂停、落地后再续播，我改成那样。
