# 03 · 还原方法与还原度

## 前提：APK 里没有源码

`BiliLite-0.4.3-android-debug.apk` 的 web 部分只有 **Vite 打包后的 chunk**：

```
assets/public/
├── index.html
├── cordova.js
├── native-bridge.js          ← Capacitor 官方桥（51 KB）
└── assets/
    ├── index-jTHZJced.js     ← 入口：Vue 应用 + 安卓数据桥（约 2600 行 prettier 后）
    ├── index-B576k3Hi.js     ← 桌面 Electron 桥（延迟代理）
    ├── index-D9UzvbUq.css    ← 全局样式
    ├── 40 个页面/库 chunk（.js）
    └── 11 个组件样式 chunk（.css）
```

- **没有 `.map` sourcemap**，原始 `.vue`/`.ts` 文件不可恢复；
- 变量名、函数名全部被压缩（`n`、`o`、`t`、`S`、`Ie`、`hr` …），但 **字符串字面量、类名、路由路径、接口地址、中文文案全部保留**——这是还原的主要抓手。

所以本工程的目标不是「字节一致」，而是：

1. **行为一致**：同样的路由、同样的接口、同样的本地表结构、同样的交互与文案；
2. **结构可读**：按原作者意图重新拆成 `.vue` / `.ts` / store / db，命名语义化；
3. **可验证**：构建通过、类型检查通过、12 个路由能在无头浏览器里真实渲染、截图可对照。

## 还原流程（工具都在 `tools/`）

### 1. 解包与美化

```bash
# 已做：复制 APK → unzip → reference/apk-dist（原样）+ reference/decompiled（美化）
npx prettier@3.3.3 --write reference/decompiled/js/*.js reference/decompiled/css/*.css
```

美化后 `index-jTHZJced.js` 从 1 行变成 2600+ 行可读结构，函数、对象、switch 分支都能逐段读。

### 2. 从产物里定位模块边界

- **组件名**：每个 chunk 里都有 `__name: "HomeView"`、`withInstall(Icon, [["__scopeId","data-v-xxx"]])`，据此确定 chunk ↔ 组件；
- **作用域样式**：`tools/map-components.mjs` 精确解析 `__scopeId`，得到 `data-v-xxxx` → 组件名映射；
- **路由**：`router-CXYtswha.js` 末尾的路由数组 + `createWebHashHistory` 完全可读，直接照抄；
- **数据契约**：`index-jTHZJced.js` 里 `gr()` 组装 `window.bili` 的代码可读，37 个 handler 名（`"video:playurl"` 等）就是通道清单；
- **Dexie**：桥 chunk 内联的 `class ... extends Dexie` 与 `.version(1).stores({...})` 链可读，库名 `study-bili`、19 张表、v1→v7 演进全部照抄。

### 3. 拆 CSS

`tools/split-css.mjs`：按产物 CSS 里的 `[data-v-xxxx]` 作用域把打包样式拆回组件级文件，去掉作用域属性与 Vite 追加的 keyframes 后缀，输出到 `app/src/styles/recovered/`；没有作用域选择器的部分合并成 `app/src/styles/global.css`（1369 行，含 `:root` 主题变量）。

产物 CSS 与拆分结果的**选择器集合做过 diff，完全一致**（子代理逐个组件校验过）。

### 4. 渲染函数 → 模板（人工 + 规则化反推）

Vue 的编译产物是 `createElementVNode / renderList / toDisplayString / withDirectives` 等调用，反推规则：

| 编译产物 | 还原成 |
|---|---|
| `createElementVNode("div", { class: "card" }, [...])` | `<div class="card">…</div>` |
| `renderList(list, (item, i) => ...)` | `v-for="(item, i) in list"` |
| `cond ? A : B` / `cond && A` | `v-if="cond"` / `v-else` |
| `toDisplayString(x)` | `{{ x }}` |
| `onClick: _cache[0] || (_cache[0] = (...a) => fn(...a))` | `@click="fn"` |
| `withDirectives(vnode, [[vShow, cond]])` | `v-show="cond"` |
| `createCommentVNode("v-if", true)` | 略 |
| `openBlock()/createElementBlock()` | 普通元素 |

`.vue` 的 `<script setup>` 也从压缩后的 `setup()` 返回对象逐项还原：refs、computed、函数、onMounted 顺序全部保留。

### 5. 并行重写 + 逐项校验

7 个子代理按「模块」分工（外壳 / 信息流 / 学习 / 习惯+本地 / 播放 / 设置+UP管理 / 数据桥），每个都：

- 只写自己负责的文件，公共契约（`types.ts`、`stores/*`、`db`、`styles`）只读；
- 用 `@vue/compiler-sfc` 的 `parse + compileScript + compileTemplate` 自检；
- 数据桥额外做了：37 个 handler 与原 `hr` 集合比对（missing/extra 均为空）、MD5 与 Node `crypto` 9 组对照、用假 Capacitor + 假 B 站 API 跑通全部 handler、`tsc --noEmit` 0 错误；
- 播放内核逐段对照 `dash-C8KLxT-Q.js`（MSE + range 拉流 + mpegts 兜底 + 错误重连）。

### 6. 最终验收

```bash
cd app
npx vite build        # 成功
npx vue-tsc --noEmit  # 0 错误
node ../tools/browser/shot.mjs http://127.0.0.1:4199/   # 12 路由截图
```

截图见 `reference/screenshots/`，逐页检查布局/文案/交互态，详见 [07-构建验收与开发者工具.md](07-构建验收与开发者工具.md)。

## 已知偏差清单（都有代码注释）

1. **`MiniPlayer` 图标**：原版用的 `size` 图标在 0.4.3 的图标表里不存在，改用 `expand`；
2. **`MiniPlayer` 换视频**：原版 dash hook 在换视频时有一处失效 bug，本工程改成 `if (!player) return`；
3. **`LoginModal` 自动刷新**：补了二维码过期自动重生成的 watch（原版要手动点）；
4. **`VideoView` UP 兜底**：个别接口 UP 名/ mid 读不到时用 `owner.name/owner.mid` 兜底；
5. **`fav.resources` 字段**：桥返回体统一成 `{info, medias, hasMore, items, page, total}`，字段同时给 `upper/upperMid` 与 `upName/upMid` 两套别名（渲染层两种读法都有）；
6. **`SettingsView.setTheme` 参数类型**收紧成 `'dark' | 'light'`（类型安全，行为不变）；
7. **番茄钟 store 拆分**：原版是 `FocusPanel.vue` 的 `<script>` 模块，本工程提成 `stores/pomodoro.ts`（多个组件共享）；
8. **新增开发者工具**（原 APK 没有，也不影响真机）：`bridge/mock.ts`、`dev/seed.ts`、`?mock=1`、`window.__*Probe` 探针保留。

## 无法还原 / 无法验证的部分

- **原始 `.vue` 源**：无 sourcemap，只能行为等价重写；
- ~~**Java 源码**：`classes*.dex` 无法反编译（无 java/jadx）…~~ → **已补全**：上游 tag 公开源码后，`app/android/` 直接采用官方 `mobile/android/`（3 个 Java 插件为逐字节真源码），dex 只用于同源验证；核对结果见 [08-与上游源码逐模块核对.md](08-与上游源码逐模块核对.md)（另：本工程基于产物的重写现在有了上游基准，逐模块差异已全部登记）；
- **真机行为**：本机没有安卓设备/模拟器，`bridge/android.ts` 的验证是「假 Capacitor 插件 + 假 B 站 API」单测级别，未在真机上跑过；
- **真实播放**：mock 模式没有真媒体流（被 CSP 拦），DASH 内核的拉流/切档只在代码层面对照过，未用真 B 站 playurl 端到端跑（需要登录与外网）。
