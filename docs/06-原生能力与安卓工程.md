## 2. Capacitor 配置

APK 里是 `assets/capacitor.config.json`（原样保留在 `app/capacitor.config.json`）：

```json
{
  "appId": "com.bililite.app",
  "appName": "BiliLite",
  "webDir": "www",
  "loggingBehavior": "none",
  "android": { "allowMixedContent": true, "webContentsDebuggingEnabled": true },
  "server": { "androidScheme": "https", "hostname": "www.bilibili.com" },
  "plugins": { "CapacitorHttp": { "enabled": true } }
}
```

要点：

- `hostname: www.bilibili.com` + `androidScheme: https` → WebView 的原生 origin 是 `https://www.bilibili.com`，Cookie 与 `Referer` 都像"在 B 站网页里"（绕防盗链的关键）；
- `allowMixedContent: true` → 允许 http 混合内容；
- `webContentsDebuggingEnabled: true` → `chrome://inspect` 可调真机 webview；
- `CapacitorHttp.enabled: true` → `@capacitor/core` 内置的原生请求生效（`app/src/bridge/http.ts` 依赖它）；
- `webDir`：APK 里是 `www`；**本还原工程改成 `dist`**，与 `npm run build` 输出对齐（所以 `cap sync` 拷的是 `app/dist`）。除此之外与 APK 内的配置**逐字段一致**。

## 5. Key 一：`MainActivity`（桌面 UA 是必须的）

`app/android/app/src/main/java/com/bililite/app/MainActivity.java`：

- `:34-35` `registerPlugin(PipPlugin.class)`、`registerPlugin(ImmersivePlugin.class)`，两条都在 `super.onCreate()`（`:36`）**之前** —— Capacitor 要求如此，晚了自己写的插件不会挂到 Bridge 上；
- `:28-29` 常量 `DESKTOP_UA = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36"`；
- `:48-58` `applyDesktopUserAgent()`：`getBridge().getWebView().getSettings().setUserAgentString(DESKTOP_UA)`，全程 try/catch（拿不到 WebView 就跳过）；
- `:60-68` `onUserLeaveHint()`：用户按 Home / 切走时，若 `PipPlugin.get().isPlaying()` 且 `Build.VERSION.SDK_INT >= O`，就 `pip.enterPip()` —— **画中画是系统习惯做法，页面上没有「小窗」按钮**；
- `onResume()`（`:41-45`）再兜底设一次 UA（Activity 重建 / 进程恢复时）。

为什么非要改 WebView UA：B 站分片 CDN（`upos-*.bilivideo.com`）**按 User-Agent 放行**，同一分片同一 Referer：桌面 Chrome UA → 206，Chrome 安卓 UA / WebView 默认 UA → 403。播放器是用 `fetch` 自己拉 DASH 分片喂 MSE 的，这些请求由 WebView 发出；接口调用走 CapacitorHttp（`bridge/http.ts` 的 `BASE_HEADERS` 本来就带桌面 UA），所以**只改 WebView 这一处就够**。

## 6. Key 二：`ImmersivePlugin`（0.4.3 的全屏黑带修复）

`app/android/app/src/main/java/com/bililite/app/ImmersivePlugin.java`：

```java
@CapacitorPlugin(name = "Immersive")            // :25
public class ImmersivePlugin extends Plugin {
  @PluginMethod
  public void setImmersive(PluginCall call) {   // :29
    boolean on = Boolean.TRUE.equals(call.getBoolean("on", Boolean.FALSE));  // :30
    ...
    WindowCompat.setDecorFitsSystemWindows(window, !on);                      // :40
    WindowInsetsControllerCompat ctl = WindowCompat.getInsetsController(window, window.getDecorView());
    if (on) {
      ctl.hide(WindowInsetsCompat.Type.systemBars());                         // :45
      ctl.setSystemBarsBehavior(
          WindowInsetsControllerCompat.BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE); // :47-48
    } else {
      ctl.show(WindowInsetsCompat.Type.systemBars());                         // :50
    }
  }
}
```

- **参数键是 `on`（布尔），不是 `enabled`** —— JS 侧 `app/src/native/pip.ts:34` 传的是 `{ on }`，上游 `src/mobile/platform.js:82` 也是 `{ on }`。文档初版写 `{enabled}` 是错的（**修正**）。
- 做这件事的原因：仅 `StatusBar.hide()` 藏不掉内容区外的系统栏占位，WebView 视口不含系统栏 → 全屏时状态栏那块是**一整条黑带**；`setDecorFitsSystemWindows(false)` 让内容铺到系统栏底下才是根治。
- 全程 `try/catch(Throwable)`：拿不到 Activity / 系统不支持就当没这回事，页面照常可用；`call.resolve()` 总是成功（JS 侧不用处理失败分支）。

## 7. Key 三：`PipPlugin`（最小画中画）

`app/android/app/src/main/java/com/bililite/app/PipPlugin.java`：

| 成员 | 行 | 说明 |
|---|---|---|
| `@CapacitorPlugin(name = "Pip")` | `:25` | 名字与 JS `registerPlugin('Pip')` 精确一致 |

## 10. 真的要打一个 APK 出来

前置：**JDK 17** + **Android SDK（platform 34 / build-tools）**。本机最初没有 JDK/SDK，后来在无 root 的 aarch64 环境里从零把工具链搭了出来，**`assembleDebug` 已实测成功**，产物就是仓库根的 `BiliLite-0.4.5-debug.apk`（4,107,722 B，versionCode 9，签名/对齐校验通过；`clean` 后重建仍是同一 sha256）。`BiliLite-0.4.4-debug.apk`（4,107,559 B，versionCode 8）与 0.4.3 的首次产物 `BiliLite-0.4.3-debug.apk`（4,107,542 B，versionCode 7）也保留在仓库根作对照。完整过程与复现命令见 [09-生成可安装APK.md](09-生成可安装APK.md)，0.4.4 增量见 [11-0.4.4同步记录.md](11-0.4.4同步记录.md)。

```bash
cd app
npm install                 # 含 @capacitor/cli（devDependency）
npm run build               # → app/dist
npm run sync                # = cap sync android：dist → android/app/src/main/assets/public
                            #   并重建 capacitor.settings.gradle / capacitor.build.gradle / cordova 空模块
echo "sdk.dir=/path/to/Android/Sdk" > android/local.properties   # 不要提交
cd android && ./gradlew assembleDebug --console=plain
# 产物：app/android/app/build/outputs/apk/debug/app-debug.apk
```

本机已执行的 `cap sync`（`@capacitor/cli` 6.2.2）结果：

- 拷入 `dist` → `app/android/app/src/main/assets/public`（含 `cordova.js`、`cordova_plugins.js`）；
- 生成 `assets/capacitor.config.json`、`assets/capacitor.plugins.json` —— 后者与 APK 原件**逐项一致**；
- `capacitor.settings.gradle` 由 pnpm 布局改写成 npm 布局：`../node_modules/@capacitor/android/capacitor`、`../node_modules/@capacitor/app/android` …（上游因为用 pnpm，路径是 `../node_modules/.pnpm/@capacitor+X@VER_.../node_modules/...`）；
- 补齐 `capacitor-cordova-android-plugins/`（`build.gradle`、`cordova.variables.gradle`、`src/main/AndroidManifest.xml`、两个 `.gitkeep`）；
- 7 个插件版本：`app 6.0.3`、`clipboard 6.0.3`、`filesystem 6.0.4`、`preferences 6.0.4`、`screen-orientation 6.0.4`、`share 6.0.4`、`status-bar 6.0.3`，`android`/`core` 6.2.2 —— 与上游 `capacitor.settings.gradle` 里锁定的版本**完全相同**。

踩坑提示（来自上游 README 与本机实测）：

- 工程路径含中文 → `android.overridePathCheck=true` 已固化在 `gradle.properties`；

## 11. 与原 APK 的差异 / 未验证

- **`webDir`**：APK 用 `www`，本工程用 `dist`（唯一的配置差异）；
- **签名**：APK 是 debug 签名；release 构建需自己配 keystore（`.gitignore` 已排除 `*.jks`）；
- **已实测**：`gradlew assembleDebug` 成功三次（0.4.3 / 0.4.4 / 0.4.5）。0.4.3：264 tasks、4m39s，产物 versionCode 7 / versionName 0.4.3；0.4.4（2026-10-25）：增量 55s、`clean assembleDebug` 冷构建 1m50s，产物 `aapt dump badging` = package `com.bililite.app` / versionCode 8 / versionName 0.4.4 / minSdk 22 / target 34，`apksigner verify` v1+v2 通过，`zipalign -c -p 4` 通过，两次构建 sha256 相同（4,107,559 B / `d7ceccfe…`）。**0.4.4 出包后原生侧（4 个 `classes*.dex`、`AndroidManifest.xml`、`resources.arsc`）与官方 0.4.4 APK 逐字节相同**，唯一差异是 `assets/capacitor.config.json` 的 `webDir`；0.4.5（2026-10-25，本机构建）：增量 16s、`clean assembleDebug` 冷构建 1m02s，产物 versionCode 9 / versionName 0.4.5，4,107,722 B / `9f0bda8d…`，两次构建 sha256 相同，原生侧与 0.4.4 产物仍逐字节相同（只有 web 层和版本号变）；
- **未验证**：真机沉浸式/画中画效果、splash 与图标在真机上的显示、安装与首启（本机无 `adb`/设备）；
- **已静态核对**：55 个 Gradle 工程文件与上游 `v0.4.3` 逐字节一致（`cap sync` 只改/生成了上文列出的 4 类文件）；`AndroidManifest` / `res/values` / `file_paths.xml` 与从 APK 解码出的资料一致；3 个 Java 类名/方法名/常量在 dex 里逐一对上。
