# 播放手势与跳转防抖（本机 0.4.34）

对应方案：[docs/39](39-播放手势与跳转方案.md)。

## 一、画面左右滑动调进度

- 手势区：视频画面（`.player-stage`），控制条/按钮区域不接管；
- 横向拖动超过 10px 且比纵向大 → 进入手势：浮层显示 `+36s  12:34 / 33:35`，松手才跳；
- 灵敏度：**画面满宽 = ±120 秒**（拖动 1/7 屏 ≈ 17 秒）；目标夹在 `[0, 总时长-0.4s]`；
- 拖动中途滑回/取消（`pointercancel`）不跳转；松手后 400ms 内抑制误触的 click，不会顺带切换播放/暂停；
- 点按（位移 < 10px）仍然切换播放/暂停；
- 触摸端双击：左半屏 −10s、右半屏 +10s（`seekStep` 设置），单击延迟 240ms 执行，避免和双击打架；
- 鼠标端保持原样：单击播放/暂停、双击全屏（`@dblclick`）。

## 二、进度条跳转防抖/串行化（修「连点无法加载」）

`app/src/player/dash.ts` 新增：

- `requestSeek(sec)`：统一入口（点击、拖动、键盘、双击都走它）；
  - 与当前位置差 < 0.5s 且已缓冲 → 忽略（点同一处不重建）；
  - 正在跳转 → 只记 `pendingSeek`（最后一次）；
  - 空闲 → `runSeek()`；
- `runSeek()`：缓冲内直接改 `currentTime`；不在缓冲才 `restartAt()` 重建一次；
  收尾时若有 `pendingSeek` 且与落点差 > 0.5s → 150ms 后只补跳最后一次；
- `restartAt()`：重建 MediaSource 并恢复原播放状态，失败自动重试 1 次，仍失败才 `onError`；
- 原生 `seeking` 事件收敛到同一个队列（`onSeeking` → `requestSeek`），不会出现两次重建并发；
- `seek()` 保留为 `requestSeek()` 的别名（小窗等旧调用不受影响）。

效果：连续猛点进度条最多触发 1–2 次重建，最后停在最后一次点的位置，不再「点了没反应」或「一直加载」。

## 四、手工验收（真机）

1. 画面横滑 100px → 浮层约 ±17s，松手画面到目标位置；
2. 横滑中途滑回 → 不跳转；
3. 点画面（不动）→ 只切播放/暂停；
4. 连续快速点进度条 20 次 → 不报错、不卡加载，3 秒内停在最后一次位置；
5. 拖动进度条 → 只在松手时跳一次；
6. 跳未缓冲区域（如 20:00）→ 重建后继续播，不出红卡片。
