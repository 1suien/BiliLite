# 「视频一直缓冲、切清晰度/分P也不动」诊断与重试（本机 0.4.53）

## 现象（用户截图 + 调试行）

```
地址 0.2s · 首块 0.3s · 首帧 16.3s · append 894次/0.5s · sz-estgcos · 221.5MB · 728.5MB/s
```

- 地址与首块都很快，但画面一直「缓冲中…」，进度停在 0:00；
- `append 894 次`、`221.5MB` 说明**数据在疯狂下载并塞进 MSE**，但缓冲没有转化成可播放画面；
- 这时再点清晰度/分P，页面主线程被大量 append 占住，操作看起来「没反应」。

## 这一版做了什么

1. **调试行加「缓冲 Xs」**：每秒刷新视频轨缓冲超前秒数。下次卡住时能直接看出是「下载很多但缓冲不涨」（`缓冲 0s` + 几百 MB）还是「缓冲正常但没播」（`缓冲 40s` + 卡 0:00），两者修法完全不同。
2. **8 秒首帧看门狗**：8 秒没有画面且视频是暂停状态 → 自动重载一次（重新拉地址+重开流）；再不行就在画面上给一个红按钮 **「加载卡住了 · 点此重新加载」**，随时能手动重试。
3. **播放成功即清空看门狗**，不会误触发。
4. 顺带修了点小问题：`firstFrameMs` 判断写错导致兜底不生效（TS 报错暴露）。

## 怎么用它

卡住时先看调试行里的「缓冲」：

| 调试行 | 判断 | 处理 |
| --- | --- | --- |
| `缓冲 0s` + 几百 MB | MSE 收了数据但没形成缓冲（编码/分片问题） | 点红色重试按钮，或换 720P |
| `缓冲 40s` + 卡 0:00 | 数据够了但没播起来（自动播放被拦） | 点一下画面 |
| `换线 N次` 一直涨 | CDN 线路不给数据 | 等它换线，或换清晰度 |
