# 把 0.6.25 的播放能力搬进 0.4.3 WebView 版

> 依据：[docs/10-播放方式对比.md](10-播放方式对比.md) 的逆向结论（原生 v0.6.25 反编译源码）
> 结论：**播放内核不可移植**（ExoPlayer 是原生 demuxer + MediaCodec 硬解；WebView 只能走 MSE），但 0.6.25 在播放页上的一批**交互与本地能力**可以 1:1 搬过来。本文记录搬了什么、在哪、默认值多少、以及为什么搬不了另一半。

## 一、移植清单

| # | 能力 | 0.6.25 出处 | 本工程落点 | 默认值 |
|---|---|---|---|---|
| 1 | 长按倍速 | `long_press_speed`（`Y2/Y.java:f7179c`，候选 2×/3×，`d(ctx)` 非表内回落 2.0） | `app/src/views/VideoView.vue` 的 `onVideoPointerDown/onVideoPointerUp`（按住 450ms → `playbackRate=longPressSpeed`，松手 `applyRate()` 恢复） | 2× |
| 2 | 双击左退/右进 | `dtap_seek_step`（`Y2/Y.java:f7178b`，候选 5/10/15/30，`c(ctx)` 非表内回落 10） | 同文件 `onStageDblClick`：鼠标位置落在画面左/右 1/3 → `seekBy(∓step, true)`，中间 1/3 保留原来的全屏 | 10 秒 |
| 3 | 连播延迟 + 可取消 | `auto_next_delay`（`Y2/Y.java:f7177a`，候选 0/3/5/10 秒，默认 3；UI 文案「N 秒后播放下一集」） | `onEnded` → `startNextCountdown()`；倒计时浮层用 `.player-msg` 显示「N 秒后播放下一 P」+ 取消按钮 | 0（立即，保持 0.4.3 原行为） |
| 4 | 播放时保持屏幕常亮 | 设置项「播放时保持屏幕常亮」（原生 `KEEP_SCREEN_ON`） | `acquireWakeLock()/releaseWakeLock()`：`navigator.wakeLock.request('screen')`，`watch(playing)` 联动，`keepAwake` 开关控制 | 开 |
| 5 | 在线字幕「秒/毫秒」判定 | `b3.dc.Q(durSec, json)`：`max(to) > max(durSec*2, 5000)` 判毫秒，否则按秒 ×1000 | `normalizeOnlineSubs()`（在线字幕归一化成秒，再进现有二分匹配） | 自动 |
| 6 | 单击/双击/长按不打架 | 原生分手势处理 | `onVideoClick` 延迟 220ms 判定（双击时取消单击的播放/暂停）；长按结束后 500ms 内吞掉那次 `click` | 自动 |

## 二、设置项

`app/src/stores/settings.ts` 的 `DEFAULT_SETTINGS` 新增 4 个键（`app/src/types.ts` 的 `Settings` 同步补齐）：

```ts
autoNextDelay: 0,     // 0/3/5/10 秒
doubleTapStep: 10,    // 5/10/15/30 秒
longPressSpeed: 2,    // 2× / 3×
keepAwake: true,      // 播放时保持屏幕常亮
```

设置页「播放」面板（`app/src/views/SettingsView.vue`）新增四组控件，并且在「恢复默认设置」里同步重置。

## 三、为什么另一半搬不过来

| 能力 | 原生做法 | 为什么 WebView 版做不到 |
|---|---|---|
| 播放内核 | ExoPlayer 1.4.1 + `MergingMediaSource`（video/audio 两条 ProgressiveMediaSource） | `MergingMediaSource` 是 ExoPlayer 的 demuxer 级能力，Web 只有 MSE：必须自己解析 `sidx`、按 `Range` 拉分片、append 两个 `SourceBuffer`（0.4.3 的自研内核已经这么做了，见 `app/src/player/dash.ts`） |
| 硬解/杜比/HDR | MediaCodec + `video/dolby-vision`、`video/hevc` | WebView 只开放 `H.264/H.265/VP9/AV1` 里设备支持的那几档，且无 API 选 decoder |
| 后台播放 | `PlaybackService` 前台服务 + 通知(4201) + 通知按钮 + 「听视频模式」 | 没有前台服务就保不住进程；`MediaSession` 在 WebView 里可设元数据但**锁屏/退后台后调度不可靠**，不搬 |
| 离线缓存/下载 | 自研下载队列（SAF 目录、`.part` 断点、`bvid_cid.video.m4s`） | 解析 m4s + 分片校验 + SAF 写盘都依赖原生；Web 侧只能做 Cache API 拼流，且与「不提供下载」的产品口径冲突 |
| 系统画中画 | 0.6.25 反而**没有**（无 PiP 字符串） | 0.4.3 有：`onUserLeaveHint` → `PipPlugin.enterPip()`（见 [docs/06](06-原生能力与安卓工程.md)） |
| 弹幕 | 0.6.25 **没有**弹幕 | — （0.4.3 也无弹幕层，见 README 已知差异） |

## 四、验证

```bash
cd app && npm run typecheck   # vue-tsc --noEmit，0 错误
cd app && npm run build       # vite build 通过
node tools/browser/shot.mjs   # 12 条路由无新增控制台错误（设置页新增控件已在 DOM 断言中存在）
```

`tools/browser` 的 DOM 检查断言：设置页存在「连播等待 / 双击跳步（左退右进）/ 长按倍速 / 播放时保持屏幕常亮」四组标签。

## 五、已知边界

- Wake Lock 只在 `https://`/`localhost` 安全上下文可用；本工程 Android 侧 origin 是 `https://www.bilibili.com`（Capacitor 配置），满足条件；桌面 `http://127.0.0.1` 也算安全上下文。
- 系统切后台会释放 Wake Lock，回前台由 `watch(playing)` 重新申请；这点与原生 `KEEP_SCREEN_ON` 不等价（原生锁屏后仍可继续播，WebView 不行）。
- 双击跳步的「左/右 1/3」按画面宽度算，竖屏/迷你窗里同样适用。
- 长按倍速不写回 `settings.playbackRate`，松手回到倍速菜单当前值 —— 与原生一致。
