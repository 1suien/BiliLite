# 软件内更新（推送新版本）方案（本机 0.4.66）

## 现在的痛点

每次出包都靠用户手动打开 `/dl/BiliLite-latest.apk` 下载安装；App 自己不知道有没有新版本，设置里「当前版本」还是硬编码的 `DATA_VERSION = '0.4.61'`。

## 目标

打开 App → 后台静默检查一次 → 有新版本时**底部滑出一条更新条**（可在设置里关）→ 点「立即更新」→ App 内下载 APK（带进度）→ 校验 sha256 → 拉起系统安装器覆盖安装（数据保留）。

不依赖 GitHub、不做 FCM 推送：APK 渠道没有实时性需求，「启动检查 + 手动检查」就够。

## 方案

### 1. 更新清单 `update.json`

构建时由脚本生成（放仓库根，`/dl/update.json` 可直接访问）：

```json
{
  "versionCode": 70,
  "versionName": "0.4.66",
  "apk": "http://127.0.0.1:3080/dl/BiliLite-latest.apk",
  "sha256": "…",
  "size": 4207933,
  "publishedAt": "2026-11-09T12:00:00+08:00",
  "notes": [
    "分P 列表从按钮左侧弹出",
    "起播卡住修复：大按钮遮罩 + 静音试播"
  ]
}
```

- 默认更新源：**本机 `http://127.0.0.1:3080/dl/update.json`**（我们出包就在这台设备上，最省事）；
- 设置里可改成任意 URL（以后想换 GitHub raw / 自建服务器都行）；
- 只接受 `https://` 或 `http://127.0.0.1/localhost`，避免明文被劫持。

### 2. 原生插件 `UpdatePlugin`（新写，`app/android/app/src/main/java/com/bililite/app/UpdatePlugin.java`）

- `current()` → `{ versionCode, versionName }`（读 `BuildConfig`，替掉硬编码的 0.4.61）；
- `check({ url })` → 原生 OkHttp 拉清单（避开 WebView 的跨域/混合内容限制），返回清单内容；
- `download({ url, sha256, name })` → 下载到 `cacheDir/update.apk`，边下边发 `updateProgress {received,total}`；**下载完校验 sha256**，不匹配就删文件报错；
- `install({ path })` → `FileProvider.getUriForFile` + `ACTION_VIEW(application/vnd.android.package-archive)` + `FLAG_GRANT_READ_URI_PERMISSION`，拉起系统安装器；
- `REQUEST_INSTALL_PACKAGES` 权限 + 首次安装前用户需在系统里给「允许安装未知应用」：
  - 没授权时返回 `needPermission`，并跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 让用户一键开；
- 安装签名不一致（比如之前装的是别的签名包）→ 系统会拒绝，界面提示「请先卸载旧版再装」。

### 3. 检查时机与频控

- 启动后 **8 秒**检查一次（不抢开屏/首屏时间）；
- 之后每 **24 小时**最多一次；同一天「稍后」的不再打扰；
- 「忽略此版本」记 localStorage，同一版本不再弹；
- 设置页「关于」里可随时**手动检查**（显示当前版本、最新版本）。

### 4. 界面

- **底部更新条**（默认不打断使用）：`发现新版本 0.4.66 · 查看详情`，点开变成卡片：更新说明（2–4 条）+「立即更新」/「稍后」/「忽略此版本」；
- 下载中：条上变进度条 + 「下载中 62% · 2.6/4.2 MB」，可取消；
- 下载完成 → 自动拉起安装器；安装返回后如果版本没变，提示「安装未完成」；
- 安装失败/无权限：给「去设置允许安装」和「在浏览器打开下载页」两个兜底按钮；
- iOS/浏览器预览：不显示更新条（插件不存在时静默跳过）。

### 5. 不自动上传 GitHub

- 更新源默认本机 `/dl/update.json`；`tools/build/update-json.mjs` 每次出包自动写清单 + 刷新 `BiliLite-latest.apk`;
- 只有你明确说「上传」时才推 GitHub；推了之后如果把更新源改成 GitHub raw，App 也能从那里检查。

## 改动文件

- `android/.../UpdatePlugin.java`（新增）、`MainActivity.java`（注册插件）、`AndroidManifest.xml`（`REQUEST_INSTALL_PACKAGES`）；
- `app/src/plugins/update.ts`（Web 侧封装）、`app/src/stores/update.ts`（状态/频控/忽略）、`app/src/components/UpdateBar.vue`（底部条 + 卡片）；
- `app/src/App.vue`（挂载更新条 + 启动检查）、`app/src/views/SettingsView.vue`（关于区：当前版本/检查更新/更新源）；
- `app/src/styles/global.css`（更新条样式）；
- `tools/build/update-json.mjs`（生成 update.json，读 APK 的 versionName/versionCode/sha256/size）；
- `docs/87`（本文）。

## 验收

1. 装 0.4.65 → 出 0.4.66 → 打开 App 8 秒内出现更新条，显示新版本号与说明；
2. 点「立即更新」→ 进度条走完 → 系统安装器弹出 → 安装后版本变 0.4.66、数据都在；
3. sha256 不匹配/下载中断 → 有明确提示，不装坏包；
4. 「稍后」「忽略此版本」生效；设置里手动检查可用；
5. 断网/服务器没起 → 静默失败，不弹任何错误。

## P1/P2（先不做）

- P1：Wi-Fi 下静默预下载、强制更新（最低版本号）、更新日志历史、stable/beta 渠道；
- P2：真正的服务端推送（FCM/WebSocket）——APK 渠道没必要，等有后台服务再说。

## 三个默认（不回就按这个）

1. 启动 8 秒后检查 + 每 24h 一次，设置可关；
2. 更新源默认本机 `http://127.0.0.1:3080/dl/update.json`，可改；
3. 更新条放底部、不强制，下载完自动拉起系统安装器。

## 实现（0.4.66）

- 原生插件 `UpdatePlugin.java`（新增）+ `MainActivity` 注册 + `AndroidManifest` 加 `REQUEST_INSTALL_PACKAGES`：
  - `current()` 用 PackageManager 读 versionCode/versionName（不依赖 BuildConfig）；
  - `check({url})`：HttpURLConnection 拉 update.json 并返回字段；
  - `download({url,sha256,name})`：下到 `cacheDir/update-*.apk`，每 200ms 发 `updateProgress`，下完校验 sha256；
  - `install({path})`：FileProvider + ACTION_VIEW；没开「安装未知应用」→ 跳 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 并返回 `needPermission`。
- JS：`src/plugins/update.ts`（封装）、`src/stores/update.ts`（状态/24h 频控/忽略版本/更新源保存）、`src/components/UpdateBar.vue`（底部更新条 + 进度）、`App.vue`（挂载 + 启动 8 秒后检查）、`SettingsView`（关于区：当前版本/检查更新/自动检查开关/更新源）、`global.css`（更新条样式）。
- `tools/build/update-json.mjs`：从 APK 生成 `update.json`（aapt2 读真实 versionCode、sha256、size、时间、说明），默认 APK 指向 `/dl/BiliLite-latest.apk`。
- 已生成：`update.json`（versionCode 70 / 0.4.66 / sha256 `77f0fdd9…` / 4,214,005 B），`/dl/update.json` 200、`/dl/BiliLite-latest.apk` 200。
- 浏览器 mock 校验：设置页「关于」出现「软件更新」区块、无 JS 报错；无原生插件时更新条静默不出现。
- **未上传 GitHub**（按新约定：只在本机构建；`BiliLite-latest.apk` 与 `update.json` 都通过本机 `/dl` 提供）。
