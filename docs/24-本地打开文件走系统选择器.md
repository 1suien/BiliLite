# 24 本机构建 0.4.17 —— 「本地 → 打开文件」改走系统文件选择器（真机上不再点不动）

> 本机定制改动。0.4.15 把安卓本地导入换成了原生 SAF 插件，但在一台平板上「打开文件」点了没反应（「打开文件夹」正常）；0.4.16 加了失败回退和诊断，用户实测**仍然点不动**（m03771："本地做的不好用，还是点不了"）。0.4.17 直接放弃在主入口上试原生，改用和「打开文件夹」**完全相同**的那条路。

## 1. 用户报告

| 版本 | 现象 |
|---|---|
| 0.4.15 | 「本地 → 打开文件」点了没反应；同一页「打开文件夹」正常 |
| 0.4.16 | 加了原生失败回退 + 诊断行，仍然「点不了」 |

关键线索：**「打开文件夹」一直可用**。它走的是 WebView 的 `<input type="file">`（`pickFolder` → `pickFilesWithInput`），而「打开文件」在 0.4.15 之后走的是原生 `LocalMediaPlugin`（`ACTION_OPEN_DOCUMENT`）。

## 2. 根因

1. 这台平板的 ROM 上，原生 `ACTION_OPEN_DOCUMENT` 这条路走不通（文档选择器被裁掉/调用后不返回），0.4.15 时点了完全没动静。
2. 0.4.16 的兜底是「9 秒没反应才切系统选择器」——用户点一下看不到任何反馈，等不到 9 秒就以为坏了，所以体感还是「点不了」。
3. 另外 `pickFilesWithInput` 里「WebView 重新聚焦后 800ms 就当成取消」的旧逻辑在真机上偏激进：选择器稍微慢一点弹出/返回，隐藏的 `<input>` 已经被移除，用户选完的文件就收不到。

## 3. 改动

### 3.1 主入口改成已验证可用的那条路

`app/src/views/LocalView.vue` 的 `pickFiles()`（「打开文件」）：

```ts
// 0.4.17：直接走和「打开文件夹」同一条 WebView <input type=file>（那条路在真机上实测能用）
const res: any = await bili.local.pickFolder()
```

- 不再先试原生，点击立即调起系统文件选择器，不会再出现「点了没动静、等 9 秒」。
- 原生导入没删，降级成诊断行里的 **「原生导入（实验）」** 按钮：成功则文件复制进 App 私有目录（刷新/重启后还在），失败会把原因写在页面上。

### 3.2 页面上留一行步骤日志

「打开文件」每走一步都往 `data-pick-trace` 那行写状态，方便真机上看清卡在哪：

```
① 正在打开系统文件选择器…（没看到弹窗就把这行截图发我）
② 选择器返回 3 个视频
③ 已加入 3 个本地视频
```

取消时写「① 选择器已取消」，异常时写「✗ 打开文件失败：…」。

### 3.3 修隐藏 input 的取消判定

`app/src/bridge/android.ts` 的 `pickFilesWithInput`：

- 加 `settled` 标记，`change` / 聚焦兜底只生效一次（避免既入库又当取消）。
- 聚焦兜底从 **800ms 固定当取消** 改成 **1500ms 且回读 `input.files`**：真的没选文件才算取消，选完再慢也能拿到文件。

### 3.4 去掉冗余入口

删掉 0.4.16 的 `pickViaInput()`（诊断行里的「改用系统文件选择器」按钮），诊断行现在是：

```
「打开文件」用的是系统文件选择器（和「打开文件夹」同一条路）；原生导入（实验）可以复制到 App 私有目录
[检测]  [系统选择器]  [原生导入（实验）]
```

## 6. 升级 / 使用

- 与 0.4.3–0.4.16 同为 debug 签名，可直接覆盖安装（versionCode 21 > 20 > … > 7）。
- 「本地 → 打开文件」现在和「打开文件夹」同一机制：选完文件立即入库；页面上那行步骤日志会告诉你走到哪一步。
- 想让文件**持久保存**（刷新/重启后还在、大文件不吃内存），点「原生导入（实验）」——能在你机器上用就皆大欢喜；不能用也没关系，主入口不受影响。
- WPS 分享接收（`ACTION_SEND`/`ACTION_VIEW`）不受这次改动影响。

## 7. 未验证 / 限制

- 真机上的系统文件选择器行为（本次只验证了 JS 侧流程与步骤日志，选择器本身是 WebView 提供的能力）；
- 「原生导入（实验）」在这台平板上是否可用，需要用户点一下看页面提示；
- 走系统选择器导入的文件仍是会话内可播（刷新后需要重新选），持久化依赖原生导入或后续再想办法。
