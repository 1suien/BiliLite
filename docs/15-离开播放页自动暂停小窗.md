# 15 本机构建 0.4.8 —— 离开播放页时视频自动缩成小圆圈并暂停

> 这是**本仓库自己的交互改动**，上游（官方 BiliLite 0.4.4）没有。0.4.5–0.4.7 的定制（笔记按分P独立、多行笔记、备份导入、圆形小窗…）都还在。

## 1. 用户要求

用户 m01609（原话）：

> 播放视频时点击左侧项目时，视频进入小窗口切暂停，先说你的理解

截图（m01608）里正在播放「新概念英语 第一册」，左侧是「学习 / 习惯 / 本地 / 首页 / UP 管理 / 收藏 / 设置」。

### 我的理解（当时先确认过）

正在看视频的时候，点左侧导航（或任何离开播放页的入口）→ 视频不该直接消失，而是：

1. 缩进右下角的小圆圈里（就是 0.4.7 做的圆形小窗）；
2. **保持暂停**，停在离开时的那一帧；
3. 点小圆圈回到播放页，**从暂停处自动继续播放**。

### 用户确认的三个点

| 问题 | 用户选择 |
|---|---|
| 什么时候自动缩窗？ | **任何页面切换都缩**（左侧导航、首页卡片、返回都算） |
| 点小圆圈回去要不要自动播？ | **自动继续播放** |
| 离开时本来就是暂停的？ | **也缩成小圆圈，保持暂停** |

## 2. 为什么原来不行

`app/src/views/VideoView.vue` 的 `onBeforeUnmount` 只做「落库 + 销毁播放器」：

```ts
flushProgress()
destroyPlayer()   // 离开播放页 = 视频直接没了
```

小窗只有**手动**入口（0.4.7 的圆形按钮 `button.mini-entry`）：`toMini()` 把视频交给 `mini.play()` 再销毁本页播放器，所以用户不点按钮就什么都留不下。

## 3. 改动

一共 3 个源文件 + 1 个验收脚本（样式没动，0.4.7 的圆气泡样式直接复用）：

### 3.1 `app/src/stores/mini.ts`：小窗增加「暂停」状态

- state 新增 `paused: false`；
- `play(v)` 里 `this.paused = !!v.paused`（默认 false = 照常播；自动缩窗时传 true）；
- `close()` 里复位 `paused` / `currentTime` / `startTime`。

### 3.2 `app/src/components/MiniPlayer.vue`：暂停态只加载不定格不动

- `load()` 里：`userPaused = !!mini.paused`、`const wantPlay = !mini.paused`、`p.load(..., autoplay: wantPlay)`；
- `!wantPlay` 时加载完立刻 `p.pause()` + `videoEl.pause()` + `mini.playing = false`（画面停在离开那一秒，继续拉流但不前进）；
- `scheduleResume()` 增加 `|| mini.paused` 守卫，避免「暂停后 1.5s 自愈」逻辑把视频拉起来；
- `.mp-badge` 图标：`mini.error ? 'refresh' : mini.paused ? 'pause' : 'play'`（暂停时显示 ‖ 而不是 ▶）；
- `.mp-tap` 的 title 改「已暂停 · 点一下回到视频页继续看；按住可拖动位置」；
- 点圆圈仍然走 `backToVideo()`（`mini.close()` + `router.push(mini.videoTarget)`，带 `t=` 进度）→ 播放页按原有逻辑自动起播，正好满足「回来自动继续」。

### 3.3 `app/src/views/VideoView.vue`：离开播放页自动缩窗

```ts
let unloadingPage = false                       // 刷新/关窗口不算「离开」
function onPageUnload() { unloadingPage = true } // window beforeunload

function autoMiniOnLeave() {
  if (unloadingPage) return
  if (mini.open) return                          // 已经在小窗里
  if (!player || !detail.value || errorText.value) return  // 没加载成功/拉流失败不弹
  if (router.currentRoute.value.name === 'video') return   // 换视频、换分P 不算离开
  const el = videoEl.value
  const at = (el && el.currentTime > 0 ? el.currentTime : 0) || current.value || 0
  const miniBvid = openedBvid || String((detail.value as any)?.bvid || '')  // 见下
  if (!miniBvid) return
  mini.play({ bvid: miniBvid, cid: cid.value, page: pageIndex.value + 1, …, startTime: at, paused: true })
  ui.toast('视频已缩到右下角小圆圈并暂停，点圆圈回来继续看')
}
```

接入点：`onMounted` 加 `window.addEventListener('beforeunload', onPageUnload)`；`onBeforeUnmount` 里移除监听，并在 `flushProgress()` 之后、`destroyPlayer()` 之前调用 `autoMiniOnLeave()`。

**踩到的坑（bvid 变空）**：`bvid` 是 `computed(() => String(route.params.bvid || ''))`。`onBeforeUnmount` 执行时路由已经切到目的页，`route.params.bvid` 已经是空 → 传过去的小窗 bvid 为空，气泡出现了但一直显示「正在获取播放地址…」，点它也不跳回播放页。修法：`onMounted` 里记 `openedBvid = bvid.value`（本页实例自己的 bvid），自动缩窗用这个稳定值。

### 3.4 不触发的场景（都验证过）

| 场景 | 行为 |
|---|---|
| 点左侧导航 / 首页卡片 / 返回 → 离开播放页 | 缩成右下角小圆并暂停 ✅ |
| 同页换分P（`?p=2`） | 不弹（路由名还是 `video`，属于组件重建） |
| 点相关推荐换到另一个视频 | 不弹（同上） |
| 刷新 / 关闭窗口 | 不弹（`beforeunload` 置位） |
| 视频没加载成功 / 拉流失败（「这条线路暂时拿不到数据」） | 不弹（没有能继续播放的东西） |
| 已经在小窗里再离开 | 不重复（`mini.open` 直接返回） |
| 手动点圆形「小窗播放」入口 | 与 0.4.7 一致：进小窗并继续播放（不是暂停） |

## 6. 升级 / 使用

- 与 0.4.5–0.4.7 同为 debug 签名，**可直接覆盖升级**（versionCode 12 > 11 > 10 > 9 > 8 > 7）；装过官方版要先卸载（签名不同）。
- 小窗里**没有**播放/暂停/切集/切清晰度按钮（0.4.7 起就是「点一下回播放页」的设计）；暂停态点圆圈 = 回播放页继续播。

## 7. 未验证 / 已知限制

- 没在真机上验证「暂停帧画面」：浏览器里是 canvas 录的 webm，真机的 DASH 流在暂停时只加载到目标位置，个别清晰度可能要等一小会儿才出画面；
- 离开时如果还在「缓冲中…」（拉流未就绪），`player` 已存在但 `errorText` 仍为空 → 也会缩成小窗，此时小窗会继续尝试拉流并显示「缓冲中…」；
- 暂停态的小窗仍会拉流（为了定格画面），如果只想省流量可以后续改成「先不加载、点回播放页再加载」。
