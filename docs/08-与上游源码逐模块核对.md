# 08 · 与官方 v0.4.3 源码的逐模块核对

> **一句话**：官方仓库 `1suien/BiliLite` 在 tag `v0.4.3`（commit `dd3e5cff`）公开了**完整原始源码**。本工程在「仅凭 APK 产物重写」之外，又把这棵树拿来当基准，对还原工程做了逐模块核对：**5 个模块域、1692 行审计报告、约 40 项机械比对**。结论是还原工程**语义等价度 94–100%**；核对中发现并**修复了 7 处真实偏差**（其中 2 处是用户可见的行为错误），其余差异全部登记在案并说明为什么保留。
>
> 核对基准：`reference/upstream-v0.4.3/`（89 个文件 / 1.1 MB，逐字节等于 `git show v0.4.3:<path>`，见 `reference/upstream-v0.4.3/PROVENANCE.md`）。

## 1. 同源证据：为什么可以拿上游源码当基准

四条独立证据链都指向「本地 APK 就是 tag v0.4.3 构建出的那一份」：

1. **APK 字节**：`.work/BiliLite-0.4.3-android-debug.apk` 4,104,453 B，sha256 `4a7b27c5…812ed2cba`，与 release notes 公布值一致。
2. **web 产物**：APK 内 `assets/public/assets/` 的 41 个 JS chunk、12 个 CSS 与上游 `mobile/`（`vite root=mobile/`、`outDir=www`）的模块切分一一对应；README 记录「pnpm run build 的 www 与 APK 内资源字节一致」。
3. **原生部分**：`classes4.dex` 里命中 `Lcom/bililite/app/{MainActivity,PipPlugin,ImmersivePlugin};`、`DESKTOP_UA` 完整 UA 串、`applyDesktopUserAgent` / `setDecorFitsSystemWindows` / `setSourceRectHint` 等方法名；`classes.dex/2/3` 里 `bililite` 引用为 0/0/9。
4. **快照校验**：`reference/upstream-v0.4.3/` 内每个已核对文件用 `git show v0.4.3:<path> | sha256sum` 与 `/tmp/up043` 对比逐字节相同（`PROVENANCE.md` 有表）。

> 反过来说：**还原工程里「与上游不同」的地方，不再能用「压缩产物看不出」解释了** —— 要么是我方重写偏差（§2，已修），要么是有意保留（§3）。

## 4. 口径说明（两个数字容易被误读）

- **「bridge 通道 37 还是 36」**：按 `'domain:action'` 字面量统计，上游 `mobile/bridge.js` 与 `app/src/bridge/android.ts` 都是 **37 条，顺序完全一致**（`tools/audit/verify-channels.mjs` 可复跑）。样式审计报告里的「36↔36」是另一套口径（按 chunk 内字符串去重、漏掉了 `http:fetch` 这类），不影响结论。
- **「还原度百分比」**：是**语义等价**的估计（文案/class/交互/数据流逐条对照），不是行级相似度；上游压缩掉了变量名，行级 diff 没有意义。

## 5. 未验证（静态核对的边界）

1. **未真正 `assembleDebug`**：环境无 JDK / Android SDK，只有 Gradle 工程与 Java 源码的静态同源核对；`cap sync` 已实测通过（见 docs/06）。
2. 真机 Capacitor 插件行为（`Filesystem`/`Share`/`CapacitorHttp` 超时）、沉浸式全屏、Home 键进 PiP、返回键优先级链——需要 Android 设备。
3. 真实 B 站接口：WBI 签名端到端只离线比对了算法（211+200+6 组通过），没有联网调 `api.bilibili.com`；`-352/-412` 风控未实测。
4. 播放内核的边界：sidx 真实落点与 206 行为、mcdn 首包延迟、`QuotaExceeded` 实测路径、安卓 WebView 的 MSE 编解码支持。
5. 像素级视觉：只做了 CSS 规则级比对 + mock 截图，未做真机逐像素对照。
6. Dexie 运行时升级路径：两侧都只声明版本链、没有 `.upgrade()` 回调，迁移行为依赖 Dexie 默认语义。
