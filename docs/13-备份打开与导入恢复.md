# 13 本机构建 0.4.6 —— 备份「打开」变成「保存」的修正 + 新增导入恢复

> 这是**本仓库自己的定制改动 + 交互修正**，上游（官方 BiliLite）0.4.4 里没有。改动完成后重新出了 APK：`BiliLite-0.4.6-debug.apk`（versionCode 10 / versionName 0.4.6）。0.4.5 的笔记改动仍然包含在内。

## 1. 用户报告

用户在 Android 平板的「设置 → 数据」里点「备份目录」右侧的「打开」，期望打开备份（或打开备份所在的目录），结果弹出的是系统「保存到…」面板，面板里还是刚才导出的那个 `bililite-learn-2026-…json`：

> 「点击打开备份，不是打开而是保存」

## 2. 根因

两件事叠在一起，都是「安卓上没有目录这个概念」却按桌面习惯画了 UI：

1. **「打开」按钮点下去走的是分享面板**：`openBackupDir()` → `bili.sys.revealPath(path)`；安卓桥里 `sys:revealPath` 的实现是「把上次导出的文件交给 `@capacitor/share`」：

   ```ts
   // app/src/bridge/android.ts
   'sys:revealPath': async () => {
     if (!lastExportUri) throw new Error('还没有导出过备份；先点「写入 JSON 备份」')
     await shareFile(lastExportUri, 'BiliLite 学习数据备份')   // dialogTitle: '保存到…'
     return true
   }
   ```

   而 `shareFile()` 里 `Share.share({ …, dialogTitle: '保存到…' })` —— 于是用户看到的就是「保存到…」。按钮叫「打开」，行为却是「另存为」，完全对不上。

2. **「备份目录」这一整行在安卓上没有意义**：安卓 WebView 拿不到真实路径，`sys:pickFile` 只会返回占位文案「本机（导出时用系统面板选保存位置）」，写入位置其实由 `backup:write` 写 `Documents`/`Cache` 后再弹系统面板决定。画一个「目录」输入框 + 选择/打开按钮，只会误导。

另外，原来只有「导出」没有「导入」：用户想「打开一份备份」，应用里根本没有这个入口。

## 3. 改动

只改了 `app/src/views/SettingsView.vue`（web 层，原生侧一行未动）。

### 3.1 安卓上隐藏「备份目录」行，改成说明

| 平台 | 数据区第一行 |
|---|---|
| 安卓（`bili.platform === 'android'`） | `备份位置` + 一句说明：「安卓上不用先选目录：点「写入 JSON 备份」后由系统「保存到」面板决定存哪（文档 / 网盘 / 微信都行）」 |
| 其它（mock/桌面预览） | 保留原来的「备份目录 + 选择/打开」，行为不变 |

这样「打开」这个名不副实的按钮在安卓上就消失了。

### 3.2 新增「恢复学习数据 → 打开 JSON 备份…」

- 隐藏 `<input type="file" accept=".json,application/json">`，点按钮触发系统文件选择器（安卓上就是 SAF 的「打开文件」面板）。
- 校验：扩展名 `.json`、体积 ≤ 32MB、`JSON.parse` 成功、`payload.app === 'study-bili'`、四个数组至少有一个非空；任一不满足只弹 toast，不动数据库。
- 确认框列出备份内容（进度 / 每日时长 / 笔记 / 清单各多少条）与合并规则，确认后才写入。
- 合并规则（不会删现有数据）：

  | 表 | 主键 | 规则 |
  |---|---|---|
  | `progress` | `key` | 同 key 取 `updatedAt` **更新**的那条（严格大于才覆盖，重复导入不会重复计数） |
  | `daily` | `date` | 同一天取 `seconds` / `videos` 的**较大值** |
  | `shelf` | `bvid` | 同 bvid 取 `at` 较新的 |
  | `notes` | 自增 `id` | 按 `bvid + cid + at + text` 去重后追加（笔记没有自然主键，只能这样判重） |

- 导入后 `await learn.init(true)` **强制**重读学习数据（`learn.init()` 默认在 `loaded` 时直接 return，不 force 的话设置页的「进度 N 条」不会变），再弹「已恢复：进度 +x · 每日时长 +x · 笔记 +x · 清单 +x」。

## 6. 升级 / 使用说明

- 与 0.4.5 / 0.4.4 同为 debug 签名，**可直接覆盖升级**；装过官方版需先卸载（签名不同）。
- 备份 JSON 格式没变（`app: 'study-bili'` + `progress/daily/notes/shelf`），0.4.5 及更早导出的文件都能被 0.4.6 导入。
- 导入是**合并**不是覆盖：想「彻底还原到某份备份」请先手动清空（学习页「清空」）再导入。

## 7. 未验证 / 已知限制

- 真机 SAF 面板的文案与可选路径（本机无 `adb`/设备，只在无头 Chromium 里用 mock 桥验证了 web 层流程）；
- 导入超大备份（几万条笔记）时逐条 `await db.put/add` 会慢，未做批量事务优化；
- 导入的 `shelf` 条目保留备份里的 `at`；`notes` 若备份里带 `id` 会被忽略（按内容去重后重新分配自增 id）。
