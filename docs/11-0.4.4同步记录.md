## 1. 上游这次改了什么

`v0.4.4` 相对 `v0.4.3` 只有 6 个文件变化，其中 3 行是代码：

| 文件 | 改动 |
|---|---|
| `src/mobile/mobile.css` | 唯一的行为改动：拆分「悬浮按钮避开手势条」规则 + 给安卓剧场模式的滚动区加 `padding-top` |
| `src/mobile/bridge.js` | `getAppVersion()` 兜底值 `'0.4.1'` → `'0.4.4'`（不影响正常路径，`App.getInfo()` 拿得到就用真版本） |
| `mobile/package.json` | `version` 0.4.3 → 0.4.4 |
| `mobile/android/app/build.gradle` | `versionCode 7 → 8`、`versionName "0.4.3" → "0.4.4"` |
| `README.md`、`mobile/README.md` | 只改说明文案（含下面这组实测数据） |

`mobile.css` 的完整改动：

```diff
-/* 悬浮按钮避开右下角的手势条 */
-html[data-platform='android'] .page-float,
-html[data-platform='android'] .theater-exit {
+/* 右下角的悬浮操作组避开手势条 */
+html[data-platform='android'] .page-float {
   bottom: calc(18px + env(safe-area-inset-bottom));
 }
+
+/*
+ * 「退出剧场」是贴右上角的固定按钮（base.css 里给的是 top: 14px; right: 14px）。
+ * 这里千万别再给它 bottom —— 它已经有 top 了，两个都给会把按钮拉成一条贯穿屏幕的竖白条
+ * （0.4.3 的真机问题：剧场模式下右侧出现一整条白色长条，还压住页面右上角的按钮）。
+ */
+html[data-platform='android'] .theater-exit {
+  top: calc(12px + env(safe-area-inset-top));
+  right: calc(12px + env(safe-area-inset-right));
+}
+
+/* 剧场模式没有顶栏，页面内容顶到最上面；给它让出一条通道，
+   免得「退出剧场」压住页面自己的右上角操作（比如学习页的「导出 JSON」） */
+html[data-platform='android'] .app.theater .scroll {
+  padding-top: 60px;
+}
```

**根因**：`.theater-exit` 在 `base.css` 里本来就是 `position: fixed; top: 14px; right: 14px`；0.4.3 的 `mobile.css` 把它和 `.page-float` 写进同一个选择器，给两者都加了 `bottom`。同时有 `top` 和 `bottom` 的固定定位元素会被拉伸到整个屏幕高度 → 竖白条。0.4.4 改为只调 `.theater-exit` 的 `top/right`，并让安卓的剧场滚动区下移 60px 给出口留通道。

上游 README 记录的真机实测：平板视口（约 1047×654）按钮 **90×36 @ (945,12)**，内容整体下移 60px。

也就是说，「原生壳一行没动、只改了 web 层的 CSS 和版本号」这个判断是从产物侧直接证实的，不依赖源码推断。

## 4. 重新出包与校验

环境与 0.4.3 首次出包相同（aarch64、无 root、JDK 17 + Android SDK 34 + Gradle 8.2.1、aapt2 经 qemu-x86_64；见 [docs/09](09-生成可安装APK.md)）。

```bash
cd app
npm run build        # vite build，✓ built in 9.46s
npm run typecheck    # vue-tsc --noEmit，0 错误
# 本沙箱 uid 无 /etc/passwd 条目 → cap sync 需要兜 os.userInfo()（普通机器不需要）
NODE_OPTIONS="--require /tmp/patch-userinfo.cjs" npx cap sync android

cd android
JAVA_HOME=/opt/toolchain/jdk17 PATH=/opt/toolchain/jdk17/bin:/opt/toolchain/usr/bin:$PATH \
GRADLE_USER_HOME=/tmp/gradle-home ./gradlew assembleDebug \
  -Pandroid.aapt2FromMavenOverride=/opt/toolchain/aapt2-bin/aapt2 \
  -Dorg.gradle.jvmargs="-Xmx900m -XX:MaxMetaspaceSize=320m" --max-workers=2 --offline
```

| 项 | 结果 |
|---|---|
| 产物 | `BiliLite-0.4.4-debug.apk`（仓库根） |
| 大小 | **4,107,559 B**（官方 0.4.4 是 4,104,456 B；差值来自签名块与 zip 条目顺序） |
| SHA-256 | `d7ceccfe86aa17e582b7b380c26f337acb62e1dd0e09bf4ad031004e5fcc81c0` |
| 构建耗时 | 增量构建 55s（29 executed / 235 up-to-date）；`clean assembleDebug` 冷构建 **1m50s**（275 tasks，230 executed） |
| 可复现 | `clean` 后重新构建的 APK 与增量构建 **sha256 完全相同**（`d7ceccfe…`），说明没有残留状态 |

校验：

- `aapt dump badging`：`package com.bililite.app`、**versionCode 8 / versionName 0.4.4**、minSdk 22、targetSdk 34、`application-label BiliLite`；
- `apksigner verify`：**v1 + v2 通过**，`CN=Android Debug`；
- `zipalign -c -p 4`：通过（`resources.arsc` 未压缩）；
- APK 内 `assets/public` 与 `app/dist` **逐字节一致**（`diff -r` 无输出）；
- 构建产物的 `index-*.css` 里三条 0.4.4 规则逐字命中；
  `html[data-platform=android] .page-float{bottom:calc(18px + env(safe-area-inset-bottom))}`、
  `html[data-platform=android] .theater-exit{top:calc(12px + env(safe-area-inset-top));right:calc(12px + env(safe-area-inset-right))}`、
  `html[data-platform=android] .app.theater .scroll{padding-top:60px}`；
- 版本兜底字符串在 `android-*.js` chunk 里能找到 `0.4.4`，`0.4.1` 已彻底消失。

## 5. 安装与升级

- 本包与官方同包名 `com.bililite.app`、同版本号（versionCode 8 / 0.4.4），但**签名证书不同**：手机里装过官方 0.4.4（或官方 0.4.3）的，要先卸载再装。
- 手机里装的是**本仓库** `BiliLite-0.4.3-debug.apk` 的，可以直接覆盖升级：同一个 debug keystore、versionCode 8 > 7。
- 未在真机上验证剧场的视觉效果（本环境无 adb / 安卓设备）；修复本身是纯 CSS 规则变化，已在构建产物 CSS 里逐条核对。
