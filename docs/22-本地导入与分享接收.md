# 22 本地视频改「原生导入」+ 支持从 WPS 分享直接播放（本机构建 0.4.15）

> 这一版做两件互相关联的事：
> 1. **B：把 App 加成「分享目标」** —— 在 WPS / 相册 / 文件管理器里对视频点「分享 → BiliLite」，直接进 App 播放；
> 2. **C：本地视频改「复制到 App 私有目录 + 原生播放」** —— 不再把整个文件读进内存，刷新、重启都不丢，大文件可以边下边播。
>
> 起因：用户想把 **WPS 网盘里的课程视频** 直接在 BiliLite 里看。

## 1. 先说结论：WPS 网盘不能「直接浏览」，但能「一键送进来播」

排查过的几条路：

| 方案 | 结论 |
|---|---|
| 把 WPS 网盘当在线播放地址 | ❌ 做不到。WPS 分享出来的是网页链接，要登录、会过期，网盘也没有公开直链 |
| 系统 SAF 目录授权（`ACTION_OPEN_DOCUMENT_TREE`） | ⚠️ 只有 WPS 自己注册了 DocumentsProvider 才能选到它的网盘；实测 WPS 基本不注册，选不到网盘里的文件 |
| WPS 开放平台 API | ⚠️ 理论可行但不现实：`access_personal_files` / `download_personal_files` 需要开发者账号 + 服务商入驻 + 应用审核，而且 OpenApi 必须在**服务端**调用并保存 APPKEY（[官方个人文件示例](https://developer.kdocs.cn/server/example/personal-files.html)） |
| **分享到 App（本版做的）** | ✅ WPS 里对视频「分享 / 用其他应用打开 → BiliLite」，App 复制一份到私有目录并直接播放 |
| **本地导入（本版顺带重做）** | ✅ 先把 WPS 文件下载到本机（或通过系统「打开文件」的 SAF 面板选到），App 内「本地 → 打开文件」导入后持久保存 |

也就是说：**拿不到「网盘直连」，但把文件送进来播这一步现在很顺**。

## 2. 根因：原来的本地播放是「内存里的临时 blob」

安卓上原来的本地导入（`app/src/bridge/android.ts`）：

```ts
// 伪路径：android://<md5 前 24 位>/<文件名>
const FILE_STORE = new Map<string, { file: File; url: string }>()   // ← 只在内存
```

- 文件通过 WebView 的 `<input type="file">` 选进来 → 存 `File` 对象 → `URL.createObjectURL` 出 blob 地址；
- **一刷新 / 一重启就没了**（`FILE_STORE` 是内存 Map），所以之前的本地视频列表一重启就「文件不在了」；
- 大文件要整个读进 WebView 内存，几个 G 的课程视频会直接把页面拖崩；
- 也没有任何「从别的 App 接收文件」的入口。

## 3. 改动

### 3.1 新增原生插件 `LocalMediaPlugin`（`app/android/app/src/main/java/com/bililite/app/LocalMediaPlugin.java`，395 行）

`@CapacitorPlugin(name = "LocalMedia")`，提供：

| 方法 | 作用 |
|---|---|
| `pickAndImport()` | 拉起系统文件选择器（`ACTION_OPEN_DOCUMENT`，`video/*` + `audio/*`，可多选），选完把文件**复制**进 `files/local-media/` |
| `sharedPending()` | 取「别的 App 分享过来、还没处理」的 `content://` URI（`ACTION_SEND` / `SEND_MULTIPLE` / `ACTION_VIEW`），复制进同一目录 |
| `probe({ paths })` | 重启后校验私有目录里的文件还在不在（只允许 `getFilesDir()` 之下的路径） |
| `discard({ path })` | 从列表移除时删掉私有目录里的那份文件 |
| `storageInfo()` | 私有目录占用情况 |

复制实现是流式的（64KB buffer，先写 `.part` 再 rename），文件名做了清洗；**同名同大小视为同一文件**（重复分享同一个视频不会多存一份，也不会丢播放进度），否则加 `-2` 后缀。

### 3.2 让 App 成为「分享目标」

- `app/android/app/src/main/java/com/bililite/app/MainActivity.java`：注册第 4 个插件；`onCreate` / `onNewIntent` 保存收到的分享 Intent（静态 `pendingSharedIntent`），新 Intent 到来时向 WebView 发 `localShare` 事件。
- `app/android/app/src/main/AndroidManifest.xml`：给 MainActivity 加 3 个 intent-filter —— `ACTION_SEND`、`ACTION_SEND_MULTIPLE`、`ACTION_VIEW`，各带 `video/*` 和 `audio/*`。
- `app/src/App.vue`：启动 / 回到前台 / 收到 `localShare` 时调 `importSharedMedia()` —— 把分享来的视频入库，单个直接 `router.push('/local/<id>')` 开始播放，多个则进「本地」列表。

### 3.3 JS 侧改成「原生路径」

| 文件 | 改动 |
|---|---|
| `app/src/bridge/android.ts` | 新增 `isNativeMediaPath()`（`/` 开头或 `file://`）、懒加载插件；`restoreEntries` 改 async：绝对路径走原生 `probe`，旧伪路径仍走内存 `FILE_STORE`；新增 `local:pickNative` / `local:sharedPending` / `local:probe` / `local:discard` / `local:storageInfo`；`local:remove` 支持连文件一起删 |
| `app/src/bridge/types.ts` / `mock.ts` / `index.ts` | 补新方法的类型、mock 实现与代理 fallback |
| `app/src/views/LocalView.vue` | 安卓下「打开文件」走原生导入；说明文案改成「存到 App 私有目录（刷新、重启后还在，大文件边下边播）」；移除原生文件时提示「会同时删掉 App 里保存的这份文件（约 X）」 |
| `app/src/views/LocalPlayerView.vue` | 注释说明两种可播 URL：blob 或 `https://localhost/_capacitor_file_…`（Capacitor 本地服务支持 Range 请求，所以能流式播） |

为什么这次能「边下边播」：Capacitor 的 `WebViewLocalServer` 对 `https://localhost/_capacitor_file_…` 支持 `Range` 请求，`<video>` 按需读文件，不用整个进内存（blob 方案做不到这一点）。

## 4. 怎么用

**WPS 网盘里的视频**
1. 在 WPS 里打开那个视频（在线预览或先下载到本机都行）；
2. 点「分享」→ 选「用其他应用打开 / 更多」→ **BiliLite**；
3. App 会自动把文件复制进私有目录并开始播放（多个文件会进「本地」列表）。

**本机已有的视频**
1. App 内「本地 → 打开文件」→ 系统文件选择器里选视频（可多选）；
2. 导入后刷新、重启都还在；删列表项时会问要不要连文件一起删。

## 7. 升级 / 兼容

- 同 debug 签名，可覆盖安装 0.4.3–0.4.14；装过官方版需先卸载。
- 旧的本地记录（`android://…` 伪路径）仍然能读出来，但**刷新后依旧会失效**（它们当初就没复制到私有目录）；重新用「打开文件」导入一次就会变成持久记录。
- 新导入的记录在私有目录 `files/local-media/`，`App 私有目录` 随卸载一起清空。

## 8. 限制 / 未验证

- 只接 `video/*` 和 `audio/*`：图片、文档、压缩包分享过来会被忽略；也**不能**在 App 里浏览 WPS 网盘目录（原因见第 1 节）。
- 复制是「等文件到私有目录再播」，网盘文件很大时第一次要等复制完成（没有做边下边播的进度条）；空间不够会失败。
- 卸载 App 会删掉私有目录里的所有导入文件（如需保留请先备份）。
- **真机未实测**（本机没有连接设备）：分享面板里能否看到 BiliLite、系统选择器多选行为、`Range` 播放是否顺畅、不同 ROM 的 `content://` 兼容性、超长文件名处理，都需要在平板上再验一遍。
- 浏览器预览里点「打开文件」走的是 `<input type="file">` 回退，不会真的复制文件。
