# 26 本机构建 0.4.19 —— 本地页只保留「本地导入」

> 用户一句话：「本地只保留本地导入」。0.4.19 把「本地」页的入口收成一个按钮，其余入口全部删掉（连同背后的扫描/诊断代码），页面只剩：一个「本地导入」、导入后的视频列表。

## 1. 用户要求

0.4.15–0.4.18 为了绕开「WPS 网盘分享不可用」，本地页陆续长出了这些入口：

| 0.4.18 时的入口 | 说明 |
|---|---|
| 打开文件 | 0.4.17 起走系统文件选择器 + 步骤日志 |
| 打开文件夹 | 多选文件模拟目录导入 |
| 扫描本机视频 | 0.4.18 加：扫 MediaStore 后勾选导入（WPS 下载到平板的兜底） |
| 检测 / 系统选择器 / 原生导入（实验） | 0.4.16–0.4.17 的排查用入口 |
| 原生导入失败原因、步骤日志 | 排查用的可见文字 |

用户觉得「本地做的不好用」，最终要求：**本地只保留本地导入**。

## 2. 改动

### 2.1 页面（`app/src/views/LocalView.vue`，789 → 457 行）

- 页头只剩一个主按钮：**`本地导入`**（`data-local-import`，`Icon folder`），空态也只剩这一个按钮；
- 删除：`打开文件`、`打开文件夹`、`扫描本机视频`、`检测`、`原生导入（实验）`、步骤日志行、扫描弹层，以及它们的状态与函数（`nativeError/nativeStuck/pickTrace/nativeDiag/nativeDiagText`、`pickFiles/pickNativeExperimental/runDiag/pickFolder`、整段 `scan*`）；
- 新增单一入口：

  ```ts
  async function importLocal() {
    const res: any = await bili.local.pickFolder()          // 系统文件选择器（多选）
    if (res?.canceled) return
    const entries = res?.entries || []
    if (!entries.length) { ui.toast('没选到视频文件（可能选的是不支持的类型）'); return }
    await importEntries(entries)                            // 入库（原生路径会复制进私有目录）
  }
  ```

  说明文字同步改成「点「本地导入」从系统选择器里选视频，安卓 APK 会把文件复制进 App 私有目录（刷新、重启后还在，大文件边下边播），浏览器预览只登记路径」。

### 2.2 后端：扫描能力一并删掉

页面入口删了，就不该再在包里带着 MediaStore 扫描与那两个权限（**装 App 时不该莫名其妙要「读取照片和视频」**），所以 0.4.18 的扫描链路整体回退：

| 位置 | 改动 |
|---|---|
| `app/android/app/src/main/java/com/bililite/app/LocalMediaPlugin.java` | 删 `scanVideos` / `scanPermissionResult` / `doScanVideos` / `importSelected` / `mediaPermissionAlias` 与 `@CapacitorPlugin(permissions=…)` 里的两个权限声明；保留 `pickAndImport` / `sharedPending` / `probe` / `discard` / `storageInfo`，以及分享过滤用的 `isMediaUri` / `isMediaName` / `MEDIA_EXTS` |
| `app/android/app/src/main/AndroidManifest.xml` | 删 `READ_MEDIA_VIDEO`、`READ_EXTERNAL_STORAGE`（`maxSdkVersion=32`）；SEND/SEND_MULTIPLE 的 `application/octet-stream` 保留（WPS 分享通用类型仍能进 App） |
| `app/src/bridge/android.ts`、`types.ts`、`mock.ts`、`index.ts` | 删 `local:scanVideos` / `local:importSelected` 的 handler、导出、类型与 mock |

保留下来的能力（都不占额外权限）：

- **本地导入**：系统文件选择器（Android 上实测可用的那条 WebView `<input type=file>` 路径）→ 原生插件把文件复制进 App 私有目录（`/data/user/0/com.bililite.app/files/local-media/`），`https://localhost/_capacitor_file_…` 支持 Range 边下边播；
- **分享接收**：WPS/文件管理器里「分享 / 用其他应用打开 → BiliLite」仍然有效（自动入库并跳播放页）；
- 列表的播放/移除/进度记忆不变（移除原生文件时会一起删私有目录那份）。

## 5. 升级说明

- 与 0.4.3–0.4.18 同为 debug 签名，可直接覆盖安装（数据保留）。
- 0.4.18 里用「扫描本机视频」导入的视频已经落进私有目录、Dexie 里也有记录，升级后照常出现在列表里；只是那个入口没了，以后用「本地导入」选文件即可。
- 如果之前给过「照片和视频」权限，新包不再声明该权限，系统里的授权会随之失效（不会再申请）。

## 6. 未验证 / 已知限制

- 系统文件选择器、复制进度、分享接收都只在浏览器里用 mock 验过 JS 侧，**真机尚未实测**（上一轮 0.4.17 的「打开文件」路径就是用户实测可用的那条，这次只是把入口合并成一个）；
- 选完文件后复制大文件需要时间（无进度条），期间页面只显示导入中；
- 卸载 App 会删掉复制进来的本地视频（列表里的记录也会没）。
