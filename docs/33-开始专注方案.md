# 33 「开始专注」方案：点一下就按计划专注（先方案，不写代码）

> 现状（0.4.29）：课表里的「开始专注」只是跳到学习页（`ScheduleView.startFocus` → `router.push('/learn')`），既不会真正开计时，也不会自动建目标和用计划时长。
> 目标（用户 2026-11-02）：**点「开始专注」→ 直接开始；第一次自动生成专注目标；时长按课表的计划时间走。**
> 本文只定方案，确认后再改代码。

## 1. 一句话流程

```
点「开始专注」
  → 取这一项的「专注目标名」（关联目标 > 时段名）
  → 没有就自动建一个（只发生在没建过 / 没这个名字的时候）
  → 绑定目标、倒计时 = 到这一项结束的剩余分钟
  → 到点：记一次专注 + 学习时长，并把这一项标记完成
```

## 2. 三个需求的落地规则

### 2.1 首次自动生成专注目标

| 情况 | 行为 |
| --- | --- |
| 这个时段关联了专注目标（`targetName`），且目标列表里有 | 直接用，不新建 |
| 关联了目标，但列表里没有 | 新建一个同名目标（颜色按现有色板轮换），并绑定 |
| 没关联目标 | 用**时段名**当目标名（「新三」「跟读」…），列表里没有就新建 |
| 时段名是「冥想/休息/运动」这类（`kind = break`） | 不显示「开始专注」，只保留「跳过/标记完成」 |
| 目标列表已到上限（现有 24 个保存上限 / 面板显示 12 个） | 不新建，直接绑定已有目标并发提示「目标已满，这次只绑定不新建」 |
| 真的新建了 | 只在新建时提示一次：「已自动创建专注目标「新三」」，后续静默 |

> 只自动建**一个**目标（就是当前要专注的那个名字），不会批量生成；用户不想要可以在学习页删/归档。

### 2.2 每次点击自动开始（不再只是跳页）

- 点击后**留在课表页**，右下角浮出「正在专注」胶囊（点它回学习页看大圆环），同时课表现在卡片变成「专注中 · 还剩 32:15」。
- 已经在专注时：
  - 点的是**同一个时段** → 「继续」（不重开一轮）；
  - 点的是**另一个时段** → 弹确认「正在专注「新三」，要中断并换到「跟读」吗？」；确认后把当前这轮按「部分完成」记账，再开新的。
- 休息块、已过去的时段：不出现「开始专注」（已过去 → 改为「补记完成」，直接标记完成并记一条手动记录）。

### 2.3 时长按计划时间

| 点击时机 | 倒计时 |
| --- | --- |
| 时段进行中 | `结束时间 − 现在`（不足 1 分钟按 1 分钟） |
| 时段还没到（点「下一项」的按钮，提前开始） | 仍然是 `结束时间 − 现在`——**结束点对齐课表，不后漂**，提前开始就等于多跑几分钟 |
| 时段已结束 | 不启动；按钮变「补记完成」 |

- 结束点固定 = 该时段的 `end`。就算中途暂停，恢复后也是回到「还剩多少到 end」，不会把结束时间往后推。
- 专注到点：`FocusSession` 记一条（`completed: true`，`task` = 目标名，`seconds` = 实际专注秒），加学习时长，同时 `slots.setStatus(今天, id, 'done')` 把这一项打完成；通知「「新三」完成，45 分钟已记录」。
- 手动「结束专注」：按「部分完成」记账（沿用现有 ≥30 秒才记的规则），该项**不**自动标完成。
- 休息：不自动进番茄休息。课表里休息是独立的块（下一项就是「冥想 15 分钟」），由时间轴自己提示；避免出现「番茄休息 5 分钟」和课表休息块打架。

## 3. 数据与 store 改动

### 3.1 `app/src/stores/pomodoro.ts`（核心）

新增一个「按计划专注」的旁路，**不改**现有番茄模式（学习页手动开始仍是 25/5 番茄）：

```ts
// state 增加
plan: null as null | {
  slotId: number | null   // 对应课表时段；手动开的计划专注可为 null
  name: string            // 目标名（= 时段名或关联目标）
  bvid?: string | null
  endAt: number           // 计划结束时间戳（对齐课表 end）
  minutes: number         // 计划总分钟（用于进度环与统计展示）
  source: 'slot' | 'target'
}

// getters 调整（plan 生效时优先）
minutesOf: (s) => (s.plan ? s.plan.minutes : (s.mode === 'focus' ? s.focusMin : s.breakMin))
totalSeconds(): number { ... }

// 新 action
async startPlanned(opts: {
  name: string
  slotId?: number | null
  bvid?: string | null
  endAt?: number          // 给了就按到点结束
  minutes?: number        // 没给 endAt 时按分钟数
}): Promise<{ switched: boolean }>
```

要点：
- `startPlanned` 里先处理「已在专注」的切换（返回 `{ switched: true }` 让页面弹确认或提示）。
- 复用现有 `start()` / `pause()` / `finish()` / 失焦校正（`visibilityHooked`）机制，只把 `endAt` 设成计划结束点。
- `persist()` 把 `plan` 一起写进 `study-bili-pomodoro`（刷新/切路由恢复；旧数据没有 `plan` 字段 → `null`，天然兼容）。
- `finish()` 里：若是 `plan` 模式且自然到点 → 记 session、加学习时长、`useSlotsStore().setStatus(today, slotId, 'done')`、通知；**不**自动切 break。手动结束照旧按「部分完成」。
- 专注记录里 `task` 用目标名（不再出现「未绑定任务」）。

### 3.2 `app/src/stores/slots.ts`

新增一个只读辅助（也可以放 ScheduleView 里）：`todayOf(id)` / `slotStatus`。暂不需要新表，`slots.setStatus` 已有。

### 3.3 `app/src/views/ScheduleView.vue`

- `startFocus(s)` 重写：

```ts
async function startFocus(s: ScheduleSlot) {
  if (s.kind === 'break' || !s.id) return
  const now = Date.now()
  const endMin = minutesOf(s.end)               // "HH:MM" → 分钟
  const endAt = todayAt(s.end)                  // 今天这一天的结束时间戳
  if (endAt <= now + 30_000) { /* 已结束 → 补记完成 */ return }
  // 1) 目标：关联目标 > 时段名；没有就建
  const targetName = await ensureFocusTarget(s)
  // 2) 开跑（含冲突确认）
  const res = await pomo.startPlanned({ name: targetName, slotId: s.id, bvid: s.bvid, endAt })
  if (res.switched) ui.toast('已切换到「' + targetName + '」', 'info', 2000)
  else ui.ok('开始专注「' + targetName + '」')
}
```

- `ensureFocusTarget(s)`：`s.targetName` 在列表里 → 用它；否则用 `s.name`（没有就用「专注」）；列表里没有 → `settings.setFocusTargets([...targets, makeFocusTarget(name, targets.length)])` 并只提示一次。
- 现在卡片：`pomo.running && pomo.plan?.slotId === 当前项 id` 时，按钮变「返回专注（还剩 mm:ss）」，否则「开始专注」。
- 进行中块（`.tl-item[data-status="doing"]`）右侧的「专注」按钮同样接 `startFocus`。
- 底部/右下「专注中」胶囊：显示目标名 + 剩余时间，点击 `router.push('/learn')`。
- 已过去的时段：按钮变「补记完成」（调 `slots.setStatus(..., 'done')` + 一次手动会话记录，`completed: false`，秒数按计划时长的一半？——不记秒数，只标完成，避免虚增学习时长）。

### 3.4 `app/src/components/FocusPanel.vue`

- 计划专注进行中时：状态文案改成「按计划 · 新三 · 到 15:45 结束」，隐藏「25/5 分钟设置」入口（避免误改），保留暂停/结束按钮与全屏圆环。
- 结束时按 3.1 的规则处理；不自动进 break。

### 3.5 其它

- `ReminderCards` 的「专注 25 分钟」按钮：保持原样（普通番茄），不接计划模式（这是提醒卡片，不是课表）。
- 版本：0.4.30（versionCode 34）。
- 文档：`docs/33-开始专注方案.md`（本篇）+ 实现后补 `docs/34`。

## 4. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 时段只剩 < 1 分钟 | 按 1 分钟开；到点即完成；提示「这一项快结束了」 |
| 点击时已过结束时间 | 不启动，改「补记完成」 |
| 正在专注时点其它时段 | 确认框；确认后当前按部分完成记账再开新的 |
| 专注中 App 被切后台/锁屏 | 已有 `endAt` 时间戳 + `visibilitychange` 校正；到点后回来会补记完成并标 done |
| 专注中改了课表（删掉该时段/改时间） | 正在跑的这一轮不受影响（`plan.endAt` 已固定）；结束后标 done 时找不到 id 就跳过并提示 |
| 目标名重复/超长 | 目标名沿用 `setFocusTargets` 的 12 字截断与去重；同时段名截断 |
| 多端/多标签同时开 | 以 `localStorage` 持久化状态为准，后开覆盖前（与现有番茄一致） |

## 5. 验收清单（浏览器 mock + 真机）

浏览器（扩展 `tools/browser/check-schedule.mjs`，用 mock 桥）：

1. 清空目标后点「开始专注」→ `settings.focusTargets` 多出「新三」，toast 提示；`pomo.running === true`、`task.name === '新三'`、`totalSeconds ≈ 计划剩余`。
2. 再点同一条 → 不新建、不重开（剩余时间继续走）。
3. 点另一条 → 出确认；确认后 task 变成新名，旧轮按部分完成记账。
4. 把 `plan.endAt` 改到 2 秒后 → 记录 +1、`slots` 该天该 id 状态变 `done`、通知出现。
5. 休息块不显示「开始专注」；已过去时段按钮显示「补记完成」。
6. 刷新页面 → 专注状态与剩余时间恢复。
7. 学习页手动番茄（25 分钟）不受影响。
8. 无 console 错误。

真机：点一次「开始专注」→ 系统通知/课表卡片显示「专注中」→ 到点自动记完成；切到 B 站看视频回来仍计时。

## 7. 待你拍板的 3 个点

1. **到点后要不要自动把该项标记完成？** 我建议要（省一次手动点）。
2. **提前点「下一项」的专注，结束点对齐课表（不后漂）** 可以吗？另一种是严格跑满计划时长（结束时间会晚于课表）。
3. **专注中切到另一个时段**：我建议「确认后切换」，也可以做成「直接切换」。
