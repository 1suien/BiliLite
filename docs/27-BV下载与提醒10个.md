## 2. 本地页新增「BV 下载」

### 为什么能直接下

B 站播放接口 `x/player/playurl` 在特定参数下会返回**单文件 MP4**（`durl`），而不是需要合轨的 DASH：

```
bvid / cid / qn / fnver=0 / fnval=1 / fourk=1 / platform=html5 / high_quality=1
```

实测（本机 curl、匿名、未登录）：

- `x/web-interface/view?bvid=BV1GJ411x7h7` → `cid=137649199`
- 上面那组参数打 `playurl` → `code: 0`、`durl` 只有 1 段、`https://….bilivideo.com/….mp4`、`size=10516124`

未登录时给的是 360P（`quality: 16` 左右），登录后能拿到更高清晰度（App 里走的是同一套带 Cookie 的请求，所以登录状态下会更清晰）。

### 链路

```
LocalView「BV 下载」弹层
  → bili.video.view(bvid) / bili.video.pages(bvid)   解析标题 + 分P
  → bili.video.downloadUrl(bvid, cid)                 api.ts 的 videoDownloadUrl
  → bili.local.download({ url, name, referer })       bridge（android.ts）
  → LocalMediaPlugin.downloadFromUrl(...)             原生 HttpURLConnection
  → App 私有目录 files/local-media/<name>.mp4
  → 入库 Dexie locals，出现在本地列表里
```

- **音/视频防盗链**：B 站 CDN 校验 `Referer` 与 UA，WebView 里 `fetch` 会被 CORS + 防盗链拦；所以下载必须在原生层做，请求头带 `Referer: https://www.bilibili.com/` 与 Chrome Mobile UA。
- **文件名**：`<bvid>-P<分P>-<分P标题>.mp4`，非法字符替换成 `_`、截到 80 字符。
- **进度**：原生每 300ms 通过 `downloadProgress` 事件推 `{ received, total, name }`，页面显示「正在下载 25%（12.0 MB / 48.0 MB）」。
- **落盘**：先写 `<name>.part`，完成再 `renameTo` 正式名，避免半截文件被当成可播视频。

### 使用

1. 本地页右上角点「BV 下载」
2. 粘贴视频链接或 BV 号（`BV1xx411c7mD`、`https://www.bilibili.com/video/BV…` 都行）
3. 点「解析」→ 显示标题与分P，点一个分P
4. 点「下载这个分P」→ 完成后面板关闭，列表里多一条，可直接播放/续播

## 5. 升级 / 兼容

- 与 0.4.3–0.4.19 同为 debug 签名，**可直接覆盖安装**；装过官方版需先卸载（签名不同）。
- 提醒时间上限放宽是纯前端归一化，旧的 8 个时间会原样保留，可以继续加到 10 个。
- 本地列表里已有的视频不受影响；BV 下载的文件同样是「App 私有目录」，移除条目时会一起删掉。

## 6. 限制 / 未验证

- **只支持能拿到单文件 `durl` 的视频**：番剧/课程/部分互动视频只给 DASH 或需要大会员，会提示「拿不到单文件下载地址」；被服务端拆成多段的会提示「暂不支持下载」。
- **没有断点续传、没有下载队列/暂停**：下载中关闭 App 会留下一份 `.part`（不会出现在列表，下次可手动清理）。后续做「下载管理」再补。
- 未登录时清晰度较低（360P 左右）；登录后会更高，但高清/大会员清晰度仍受账号权限限制。
- 真机未实测：本次只验证了浏览器里的 UI/调用参数与 APK 打包含义（原生下载逻辑需要真机跑一次确认能落盘、能播）。
- 下载占用空间没有上限控制（B 站一个 30 分钟视频约 100–300MB）。
