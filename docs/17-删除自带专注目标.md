# 17 本机构建 0.4.10 —— 删掉「自带的专注目标」

> 这是**本仓库自己的定制删减**，上游（官方 BiliLite）没有。改动完成后重新出了 APK：`BiliLite-0.4.10-debug.apk`（versionCode 14 / versionName 0.4.10）。0.4.4–0.4.9 的定制改动仍然包含在内。

## 1. 用户报告

学习页「专注目标」面板里一开始就有四个目标：阅读 / 刷题 / 看课 / 整理笔记，用户用红圈圈住这四行，说：

> 「删除自带的目标」

（m02103）

这四行来自代码里的默认值，不是用户自己加的——用户想要的是一个干净的列表，目标全部自己添加。

## 2. 根因

三处代码叠在一起，把「默认专注任务」写成了「默认专注目标」：

1. `app/src/stores/settings.ts` 里 `DEFAULT_FOCUS_TASKS = ['阅读', '刷题', '看课', '整理笔记']`，而 `DEFAULT_SETTINGS.focusTasks` 也用它。
2. `settings.init()` 首次启动时有一段「把默认专注任务写成专注目标」：

   ```ts
   if (!Array.isArray(this.settings.focusTargets) || !this.settings.focusTargets.length) {
     const tasks = ...focusTasks...           // 缺省就是那四个
     const targets = tasks.map((t, i) => makeFocusTarget(t, i)).filter((t) => t.name)
     if (targets.length) await this.setFocusTargets(targets)
   }
   ```

   所以全新安装一打开学习页，四个目标就已经躺在列表里了。
3. UI 里还有两个「恢复默认」入口，会把列表重新变回那四个：
   - `FocusTargets.vue` 头部的刷新按钮（`title="恢复默认目标"`）；
   - `FocusPanel.vue` 的「恢复默认」按钮。

## 3. 改动

| 文件 | 改动 |
|---|---|
| `app/src/stores/settings.ts` | `DEFAULT_FOCUS_TASKS: string[] = []`（注释说明「不再自带目标」）；`DEFAULT_SETTINGS.focusTasks: []`；**删掉 `init()` 里的自动写目标逻辑**，换成一次性迁移（见下） |
| `app/src/stores/settings.ts` | 迁移：`if (!this.settings.focusPresetsCleared)` 时，若 `focusTargets` 恰好就是旧版四个预设（名字集合完全等于 阅读/刷题/看课/整理笔记）→ `setFocusTargets([])` 清空；然后 `patch({ focusPresetsCleared: true })` 落一个标记，之后永不再跑 |
| `app/src/bridge/state.ts` | 原生侧 `DEFAULT_SETTINGS.focusTasks` 由四目标改 `[]`（新装/清数据后的缺省值） |
| `app/src/bridge/mock.ts` | mock 桥的 `focusTasks` 同样改 `[]`（浏览器预览与验收脚本用） |
| `app/src/components/FocusTargets.vue` | 删 `restoreDefaults()` 与头部刷新按钮（`title="恢复默认目标"`），import 去掉 `DEFAULT_FOCUS_TASKS` |
| `app/src/components/FocusPanel.vue` | 删 `restoreDefaults()` 与「恢复默认」按钮，import 去掉 `DEFAULT_FOCUS_TASKS` |

### 为什么用「一次性迁移」而不是直接删默认值

用户平板上已经存了那四个目标（0.4.9 及更早版本写进 `settings.focusTargets` 的）。只改默认值的话，老安装升级上来还是那四个，等于没删。所以升级后第一次启动：

- 如果列表**正好**是旧版四个预设 → 清空，并写 `focusPresetsCleared: true`；
- 如果不是（用户自己增删过）→ 不动；
- 之后永不再判断（`focusPresetsCleared` 已存在）。

## 4. 行为变化

| 场景 | 0.4.9 及更早 | 0.4.10 |
|---|---|---|
| 全新安装打开学习页 | 列表里已有 阅读/刷题/看课/整理笔记 | **空**，显示「还没有目标，点右上角 ＋ 加一个。」 |
| 从旧版升级 | 保留那四个 | 一次性清空（一次性标记写库） |
| 自己加的目标 | — | 保留；刷新/重启不会被误删 |
| 「恢复默认」入口 | 有（两处） | **已删**，想加目标只能自己点 ＋ |
| 历史专注记录 | 保留（记录里显示当时的名字） | 保留，同样显示当时的名字（例如已删掉的「阅读」记录仍显示「阅读」） |

## 7. 升级 / 使用说明

- 与 0.4.3–0.4.9 同为 debug 签名，**可直接覆盖升级**；装官方版需先卸载。
- 升级后第一次打开学习页，旧的四个预设会被清掉（一次性）；想恢复它们就自己点 ＋ 加回去——**加过的名字不会被再次清掉**，因为迁移标记已经写库。
- 专注记录不会丢：已删除目标的历史记录仍然按当时的目标名显示，并计入概览/记录列表。
- 如果哪天想重新验证迁移逻辑：清 App 数据（或浏览器里删 `bililite.mock.settings`）再从旧版升级即可。

## 8. 未验证 / 已知限制

- 真机上的迁移只在浏览器 mock 存储上验证过（同一套 `settings.init()` 代码路径）；真机本轮没有设备可测。
- 备份 JSON 里**不含设置**（`backup:export` 只写 `progress/daily/notes/shelf`，学习页「导出 JSON」多写 `checkins/upTime/focus/habits/habitLogs`），所以专注目标不会被备份、也不会因为导入备份而回来；但这也意味着「目标列表」本身没有备份，换机/清数据后需要重新加。
- `app/src/dev/seed.ts`（仅 mock 演示数据）里专注记录仍用那四个名字当示例任务名，不影响真实使用。
